## 二、怎么打开原型

直接双击 `prototype/index.html`（纯静态，无构建、无依赖、无网络请求）。所有患者数据为合成示例，页面底部已标注。

**患者端（12 屏）**

| 屏 | 看什么 |
|---|---|
| 建立档案 | 微信带出姓名性别年龄、病种多选、拍药盒自动填药、紧急联系人 |
| 今天 | 三件事（量血压 / 吃药 / 走动）+ 近 2 周趋势 + 「别断」坚持天数 |
| 打卡 | 输入 178 / 108 提交 → 红灯升级「已通知李护士 · 15 分钟内回电」 |
| 指标 · 血糖 | 四分段（空腹 / 早餐后 / 午餐后 / 睡前），输入 12.1 → 黄灯；6.8 → 绿灯 |
| 指标 · 体重 | 症状多选（夜里憋醒 / 躺平就喘 / 脚踝水肿），心衰规则生效 |
| 用药 | 剩余天数、依从率、漏服补记 |
| 报告解读 | 拍照识别 → AI 草稿 → 点「模拟：医生在后台点了确认」看状态流转 |
| AI 管家 | 问「我能不能停药了？」看拒答 + 转人工；问「他汀能不能晚上吃？」看知识库回答 |
| 复诊预约 | 6 个时段（2 个已满），选中后按钮文案跟随 |

## 三、设计取向（A 方向·处方笺）

暖白纸底 `#FAF7F2` + 墨绿 `#2F5A4A` + 宋体大标题 + 1px 发丝线 `#E3DCD0`，无阴影无圆角卡片。理由：目标用户 60–75 岁，需要高对比大字与克制配色；同时避开「紫渐变 + 圆角卡 + emoji 图标」的 AI 感。红色 `#B4453A` 只用于红灯与超限，琥珀 `#B07D20` 只用于黄灯，赭石 `#A8623C` 只用于强调数字。

## 四、重新截图 / 校验

```powershell
$env:NODE_PATH="$env:APPDATA\npm\node_modules"
node _tools/verify.js     # 跑完整交互流程，输出 shots/*.png 与 shot-full.png，末尾打印 errors
node _tools/shot.js prototype/index.html prototype/shot-full.png 1500 1100 true
```

依赖全局安装的 `playwright`，脚本内自动探测本机 Edge/Chrome 作为可执行文件（缓存缺 headless shell 时直接用 `executablePath` 指向 Edge）。

## 五、已知边界

- 搜狗微信搜索的正文页会 302 到 `antispider`，**只能拿到标题 + 摘要级信息**，没有抓取全文。文章清单里的判断基于标题、摘要与公开转述，已在研究文件中按可靠性分级。
- 原型里的指标数值、患者姓名、工单号均为合成数据；「血糖达标率 17.8%→44.2%」这类数字来自公开文章的宣称，无原始出处，PRD 中已标注为「仅示意」。
- PRD 的判级阈值按「在管患者」口径设定（≥175/105 触发红灯），比诊室诊断阈值低一档，需由合作机构医生确认后实施。
- 「一个护士管 80–150 人、80% 时间打无效电话」是内部观察而非公开研究，证据链里标为需存疑，试点期第一件事是用真实排班表替换。
