## 一、真实问题分析

### 1.1 问题不是「缺知识」，是「缺执行」

公众号生态扫描（见 `research/公众号扫描.md`）里，四类内容供给方 —— 医院宣教号、学术媒体、产业媒体、私域招商号 —— 唯一的共识是：

> 「慢病管理最大的痛点，是患者**知晓规范、难以践行**。」 —— 勤成健康科技
> 「**失访**，是长期管理最难迈过的一道坎。」 —— 呼吸界（华西 ILD 全程管理）
> 「传统慢病管理的死结：**人一离店，服务就断**。」 —— 老卢说创业

患者出院/离店时拿到的是一份"应该怎么做"的清单（低盐、按时吃药、每周测三次血压），
但没有任何系统把它翻译成**今天几点、做什么、做没做、没做怎么办**。
结果是：前 2 周热情、第 3 周漏测、第 6 周断药、第 3 个月失访、第 8 个月因急症再次入院。

### 1.2 五条可验证的痛点

| # | 痛点 | 现场表现 | 现有工具为什么没解决 |
|---|---|---|---|
| P1 | **失访** | 患者「感觉好了就不来了」；电话打不通、换号、子女代管 | 随访靠 Excel + 人工记忆，无人知道谁已经 30 天没动静 |
| P2 | **用药断档** | 药吃完了不复诊、复诊了不开长期处方 | 没有"剩余药量"这个概念，提醒只能靠患者自觉 |
| P3 | **知晓但不执行** | 知道要测血压，但"今天忙，明天吧" | 科普内容只讲道理，不给**当天的最小动作** |
| P4 | **基层人力被随访吃掉** | 一个护士管 80–150 人，80% 时间在打无效电话 | 无分层、无优先级，红黄绿一起打 |
| P5 | **数据孤岛** | 院内 HIS、家用血压计、微信聊天记录三处不通 | 要么买重 HIS 集成，要么纯手工 |

### 1.3 为什么现在能做

- 支付方现实：国内没有保险买单，可收钱对象只有**机构 / 药企器械 / 药店诊所 / 患者本人**四类（动脉网：国外靠 B 端团险，国内缺稳定付费方）。→ 产品必须是**给机构用的作业系统**，患者端免费。
- 形态现实：中老年装不了新 App，「初诊在线下、复诊在线上、管理在私域」已是行业默认路径。→ 落在**微信 + 企微**里。
- 技术现实：报告 OCR、语音外呼、话术生成已经足够便宜可用，且都落在**"辅助"而非"诊疗"**的安全区内。

### 1.4 明确不做（避免范围爆炸）

- ❌ 不做 HIS/EMR 深度集成（只做 CSV/截图/OCR 导入）
- ❌ 不做在线问诊与处方流转（不碰《细则》红线）
- ❌ 不做药品电商与履约
- ❌ 不做硬件（只做蓝牙血压计/血糖仪的**数据接入协议**）
- ❌ 不做 C 端自助付费订阅（首年）

## 二、用户角色与权限

| 角色 | 入口 | 核心诉求 | 关键权限 | 不能做 |
|---|---|---|---|---|
| **患者** | 微信小程序 / 公众号菜单 | 今天该做什么、我的指标怎么样、有问题问谁 | 打卡、上传报告、看自己的数据、申请复诊 | 看他人数据、改分层、看 AI 原始草稿 |
| **家属（代管）** | 患者授权后绑定 | 爸妈今天做了吗、异常了怎么办 | 代打卡、接收预警、看趋势 | 改用药方案 |
| **健管师 / 护士** | 企微侧边栏 + Web 工作台 | 我今天该打哪 30 个电话 | 建档、随访、发任务、处置预警、改分层（黄绿） | 开处方、改诊断、把红灯直接关掉 |
| **医生** | Web 工作台 | 快速确认 AI 建议、看趋势、决定复诊 | 确认/驳回 AI 报告解读、改分层（红）、开复诊单 | 批量刷确认（需逐条留痕） |
| **机构管理员** | Web 后台 | 看整体、配规则、管人 | 规则配置、账号、数据导出、计费 | 看患者聊天明细（默认脱敏） |

**权限模型**：RBAC + 数据域（机构 → 团队 → 我的患者）。所有写操作留 `operator_id + role + timestamp`。

## 三、使用场景拆解

### 场景 A｜建档（Day 0，诊所现场，3 分钟）
护士用企微扫码，调出建档表单 → 拍病历本/出院小结 → OCR 抽取诊断、用药、最近检验 → 确认 → 系统给出**初始分层**与**首周任务包** → 打印/推送一张"你的 7 天课表"给患者。
> 成功标准：单患者建档 ≤ 3 分钟；OCR 字段准确率 ≥ 90%，人工可改。

### 场景 B｜日常打卡（Day 1–300，患者家里，40 秒）
早上 7:30 微信服务通知：「张阿姨，今天该测血压了」。点进去 → 大字号输入框（或拍血压计屏幕自动识别）→ 提交 → 立刻看到「今天已达标 · 连续 12 天」。
> 成功标准：从点通知到提交 ≤ 40 秒；60 岁以上用户首次成功率 ≥ 85%。

### 场景 C｜异常升级（红灯，15 分钟内）
患者录入 178/108 → 系统判红 → 患者看到「这个数值偏高，我已通知你的健康管家李护士」+ 三条即时处置提示（静坐复测/不要自行加药/出现胸痛立即 120）→ 企微同时推给健管师 → 健管师 15 分钟内电话 → 记录处置结果 → 必要时转医生。
> 成功标准：红灯 24h 处置率 ≥ 95%；误报（复测正常）可一键降级并记录。

### 场景 D｜报告解读（月度，2 分钟）
患者拍化验单 → OCR → 结构化（项目/值/单位/参考区间）→ AI 生成通俗解读草稿（"你的糖化血红蛋白 7.8%，比上次降了 0.4，还是高于目标 7.0，说明这三个月整体不错但晚饭主食还可以再减一点"）→ **医生在工作台点确认** → 患者收到。
> 成功标准：AI 草稿被采纳率 ≥ 70%；医生单份确认耗时 ≤ 30 秒。

### 场景 E｜随访作业（健管师，每天上午）
打开工作台 → 「今日待处理 47」按优先级排序（红灯 > 逾期随访 > 连续 3 天未打卡 > 到期复诊）→ 逐条点开，右侧显示患者 30 天轨迹 + AI 生成的话术草稿 → 打电话/发微信 → 一键记录结果（已联系/未接/拒访/已复诊）。
> 成功标准：人均在管数从 80 提升到 200；单条随访记录 ≤ 20 秒。

### 场景 F｜复诊转化（到期前 7 天）
系统识别"药量剩 7 天"或"距上次复诊 85 天"→ 推复诊提醒 → 患者在页面内选时段 → 生成预约 → 到院签到 → 医生看到"本次复诊前 30 天数据摘要"。
> 成功标准：到期复诊转化率 ≥ 45%。

## 四、业务流程梳理

### 4.1 主状态机（患者级）

```
[待建档] --建档--> [在管·绿] 
                      |  指标超标但未达危险值 / 打卡率<70%
                      v
                   [在管·黄] --连续达标 14 天--> [在管·绿]
                      |  危险值 / 症状报警 / 失访
                      v
                   [在管·红] --医生处置+连续达标 7 天--> [在管·黄]
                      
[在管·任意] --14 天无任何互动--> [失访] --触达成功--> [在管·原层]
[在管·任意] --转诊/住院--> [暂停] --出院--> [在管·红]（强制复查）
[在管·任意] --患者申请退出--> [结案]（保留数据，停止触达）
```

### 4.2 任务生成规则（规则引擎，可配置）

任务 = `病种 × 分层 × 阶段` 查表，输出当天任务清单：

| 病种 | 阶段 | 绿 | 黄 | 红 |
|---|---|---|---|---|
| 高血压 | 稳定期 | 血压 2 次/周 + 服药 + 步数 | 血压 1 次/日 + 服药 + 症状 | 血压 2 次/日 + 服药 + 每日症状 + 每周电话 |
| 2 型糖尿病 | 稳定期 | 血糖 2 次/周 + 服药 + 饮食记录 | 血糖 1 次/日（隔日空腹/餐后） | 血糖 2 次/日 + 足部检查 + 每周电话 |
| 慢阻肺 | 稳定期 | 症状评分 1 次/周 + 吸入剂 | 每日症状 + 吸入剂 + 呼吸训练 | 每日症状 + 血氧 + 48h 内随访 |

> 规则以 JSON 存储，管理员可改阈值与频次，**不写死在代码里**。

### 4.3 异常判级（示例阈值，需按机构指南校准）

| 灯 | 条件（任一） | 规则码 |
|---|---|---|
| 🔴 红 | SBP ≥ 175 或 DBP ≥ 105（在管患者阈值较诊室诊断阈值下移一档）；SBP < 90；FBG ≥ 13.9 或 < 3.9；餐后 2h 血糖 ≥ 16.7；血氧 < 90%；胸痛/呼吸困难/意识改变；自述「停药 > 3 天」 | R-BP-01…04 / R-GLU-01/02/04 / R-SPO-01 / R-SYM-01 / R-MED-01 |
| 🟡 黄 | SBP ≥ 150 或 DBP ≥ 95；FBG ≥ 10.0；餐后 2h 血糖 11.1–16.7；7 天打卡率 < 50%；连续 3 天漏服；体重 1 周增 > 2kg（心衰）；3 天涨 > 2kg 或出现水肿（心衰） | R-BP-05 / R-GLU-03/05 / R-ADH-01 / R-MED-02 / R-WT-01 |
| 🟢 绿 | 其余 | — |

> 餐后血糖阈值原 PRD 未覆盖，已在 [`docs/功能规格.md`](docs/功能规格.md) 附录 C（Q1）补齐并记为待临床顾问确认项；规则码与阈值区间在功能规格 §26.3 逐条给出「可调区间 + 产品安全底线」（红灯不允许比 175 更宽松，防止机构为降投诉把红线调高）。

判级结果**永不直接告知患者"你有病/没病"**，只给"偏高/偏低/需要复测/已通知你的管家"。

## 六、AI 能力设计（回答"接入 AI 能做什么"）

**总原则**：AI 只做「整理、解读、生成草稿、排序、触达」，**不做诊断、不开处方、不改药、不替代签字**。每条 AI 输出必须落在一个"人确认"的动作上（可配置白名单：纯科普类免确认）。

### 6.1 六个真正能省人力/换收入的位置

| # | 能力 | 输入 | 输出 | 谁受益 | 可量化收益 | 护栏 |
|---|---|---|---|---|---|---|
| AI-1 | **报告解读** | 化验单/检查单照片 | 结构化指标 + 通俗解释 + 与上次对比 + 3 条行动建议 | 患者、医生 | 医生单份解读从 5 分钟 → 30 秒确认 | 必须医生确认后可见；不写"诊断"字样；标注"AI 辅助生成" |
| AI-2 | **随访话术生成** | 患者 30 天轨迹 + 本次随访目的 + 分层 | 企微/短信文案 + 电话开场脚本 + 3 个可能异议的应答 | 健管师 | 触达回复率提升（试点目标 +20%） | 禁用"根治/逆转/保证"词库；不承诺疗效 |
| AI-3 | **待办优先级排序** | 全量患者当日状态 | 「今天先打这 30 个电话」的排序与理由 | 健管师、机构 | 人均在管 80 → 200 | 排序理由必须可解释（规则 + 模型混合） |
| AI-4 | **内容生产** | 病种 + 季节 + 机构口径 | 公众号科普、社群日报、患教卡片、7 天课表 | 机构运营 | 宣教号周更 1 篇 → 日更 3 条 | 医学事实需检索增强并给出处；发布前人工过 |
| AI-5 | **患者问答（RAG）** | 机构知识库 + 患者档案摘要 | 回答"这个药能空腹吃吗" | 患者 | 减少 40% 重复咨询 | 拒答清单：诊断、剂量调整、急救判断、情绪危机 → 一律转人 |
| AI-6 | **语音外呼** | 随访任务 + 脚本 | 多轮对话 + 结构化回收（是否服药/有无不适/是否复诊） | 健管师 | 单日触达量 ×10 | 首句必须表明"AI 助手"；随时可转人工；录音留存 |

### 6.2 AI-1 报告解读的实现骨架

```
1. OCR / 版面还原      → 项目名、结果、单位、参考区间（表格结构）
2. 规则归一            → 映射到标准检验项目字典（LOINC 子集 / 机构字典）
3. 计算                → 是否超参考区间、与上次差值、变化率
4. LLM 生成（受控）     → 输入只给结构化数值，不给原图全文；
                         prompt 明确：不得推断诊断、不得给用药剂量、
                         必须引用"参考区间"、必须给 3 条以内可执行建议
5. 事实校验            → 数值回填校验（LLM 输出的每个数字必须存在于输入）
6. 分级                → 无异常 / 需关注 / 建议尽快复诊（由规则定，不由 LLM 定）
7. 人确认              → 医生采纳 / 编辑 / 驳回（驳回原因入库，用于迭代）
8. 患者可见            → 加"由 XX 医护审核 · AI 辅助生成"水印
```

**评测集**：200 份脱敏真实报告（覆盖血常规、生化、糖化、尿微量白蛋白、肺功能）。
**验收线**：数值抽取准确率 ≥ 98%；分级与医生判断一致率 ≥ 90%；"危险级别误降" = 0（宁高勿低）。

### 6.3 AI-5 问答的拒答清单（硬编码，优先级高于模型）

`确诊/我是不是得了` `该吃什么药/加多少量/能不能停` `这个症状严重吗/要不要去医院` `急救/胸痛/昏迷/出血` `怀孕/儿童剂量` `情绪危机/自伤`
→ 命中即输出固定话术 + 一键呼叫健管师 + 记录事件。

### 6.4 模型与成本

- 主力：通用大模型 API（解读/生成/问答）；不训练基础模型。
- 检索：机构知识库（指南摘要、本院宣教、药品说明书）向量化，pgvector。
- 成本估算（与 [`docs/AI设计.md`](docs/AI设计.md) 第六章口径一致，此处为概数）：单患者月均 AI 调用 ≈ 10 次（0.9 次报告解读 + 6 次问答 + 3 次话术生成），按中等价位模型约 **0.3–0.5 元/人/月**；语音外呼另计（约 0.59 元/通，按每月 15% 患者需要外呼折算）。
- 3000 人在管机构实测口径：AI 成本约 **1,265 元/月**（人均 0.42 元），其中语音外呼占 51%、RAG 问答占 36%、其余四项合计 13%。基础版（9,800 元/年）AI 占比 18%，毛利承压点不在 AI 而在实施人力（约 2,400 元/月）。

## 七、异常与边界场景

| 场景 | 处理 |
|---|---|
| 患者录错值（178 实际 117） | 红灯页提供"我录错了，重新录"，重录后自动降级并留痕，不算误报 |
| 患者失联（电话空号/拒接 3 次） | 自动转家属联系人 → 仍失败 → 标记「失访·不可达」→ 进机构月报 → 建议线下家访工单 |
| 家属代管但患者不认可 | 授权可撤销；撤销后家属立即失去数据访问 |
| 医生 48h 未确认 AI 解读 | 自动提醒 → 72h 升级给团队负责人 → 患者端显示"解读排队中，已催办" |
| AI 输出与参考区间矛盾 | 事实校验层拦截，转人工，不进患者端 |
| 网络差/无微信 | 短信兜底通道（只发提醒与复诊，不含数据） |
| 患者急症 | 任何页面固定悬浮「紧急情况请拨 120」，不进 AI 对话 |
| 机构换系统/退租 | 全量数据导出（CSV + PDF 档案），30 天后删除 |
| 多人共用一台手机 | 支持切换档案（最多 3 人），默认记住上次 |

## 九、指标与验收

### 9.1 指标体系

| 层级 | 指标 | 定义 | 首年目标 |
|---|---|---|---|
| **北极星** | 30 天活跃管理率 | 近 30 天有 ≥1 次有效互动（打卡/问答/随访）的在管患者占比 | ≥ 60% |
| 核心 | 失访率 | 连续 14 天零互动的在管患者占比 | ≤ 15% |
| 核心 | 红灯 24h 处置率 | 红灯 alert 在 24h 内 closed 的比例 | ≥ 95% |
| 效率 | 健管师人均在管数 | 在管患者数 / 健管师数 | 80 → 200 |
| 效率 | AI 解读采纳率 | adopted / (adopted + rejected) | ≥ 70% |
| 业务 | 复诊转化率 | 到期后 14 天内到院复诊占比 | ≥ 45% |
| 质量 | 危险级别误降数 | AI/规则把红灯判成黄绿 | = 0 |
| 商业 | 机构续费率 | 第二年续费机构占比 | ≥ 80% |

> 刻意**不用「血糖达标率」做北极星**：它是失访与依从性的下游结果，周期长、噪声大、且极易被选择性呈现。

### 9.2 MVP 上线验收（8 周后必须全绿）

1. 3 家试点机构、合计 ≥ 300 名在管患者跑满 30 天
2. 建档 ≤ 3 分钟、打卡 ≤ 40 秒、随访记录 ≤ 20 秒（各测 20 次中位数）
3. 红灯全链路（录入→判级→通知→处置→留痕）在真实场景跑通 ≥ 50 次
4. AI 解读在 200 份评测集上达到 6.2 的验收线
5. 30 天活跃管理率、失访率可从看板直接读出，与明细对得上

## 十、合规红线（做成产品结构，不是免责声明）

| 红线 | 产品结构如何保证 |
|---|---|
| 医生本人接诊开方，AI 不得替代 | 系统内**没有**开处方入口；AI 输出无处方字段；复诊只生成"预约单" |
| 禁先药后方、禁 AI 自动生成处方 | 药品模块只做「记录与提醒」，不做「推荐与下单」 |
| 首诊不得线上 | 建档必须由机构在**线下**完成（扫码发生在诊室），线上只做复诊与随访 |
| 患者知情同意 | 首次使用强制签署《健康管理服务知情同意书》，个人健康信息单独授权，可撤回 |
| AI 生成内容可追溯 | 患者可见的每条 AI 内容带 `ai_log.id`、模型版本、确认人、确认时间 |
| 广告与疗效宣称 | 内置违禁词库（根治/逆转/治愈/保证/替代药物），AI 生成与人写文案双向扫描 |
| 数据合规 | 境内存储；敏感字段加密；导出脱敏；机构退租 30 天后删除；操作审计留存 3 年 |
| 急救场景 | 全局悬浮 120 入口；AI 对话命中急症词立刻中断并给出急救指引 |

| 质疑 | 回应 | 是否改方案 |

| 「又一个打卡工具，患者凭什么坚持 300 天？」 | 打卡不是目的，「三件小事 + 有人接住」才是。核心机制是**失访会被主动捞回来**，不是靠自律。首月留存靠护士首周 2 次电话。 | 不改，但把"首周人工介入"写成 P0 硬规则 |

| 「医院凭什么用你的而不买大厂？」 | 大厂做院内，我们做**院外那 300 天**，且能嵌进企微原生作业。集成成本近乎零（CSV/截图导入）。 | 不改，明确"不做 HIS 集成"为卖点 |

| 「8 周做不完。」 | 砍：C-05/C-06/C-07/C-08 全部推到 P1，MVP 只保留建档-任务-打卡-预警-随访-看板这条主线。 | 采纳，MVP 范围已按此收敛 |
| 「患者隐私，家属能看到多少？」 | 默认只看"做没做 + 异常"，不看具体数值；患者可逐项授权。 | 加授权粒度控制 |

## 十三、风险与开放问题

**风险**
1. **冷启动**：机构有患者但没护士执行 → 需要"代运营"服务包（首月驻场/远程陪跑）。
2. **医生不确认**：AI 解读卡在确认环节会废掉整个功能 → 必须把确认做到 30 秒内，并给"批量确认低风险项"。
3. **政策变化**：互联网诊疗细则若进一步收紧，复诊预约模块需可一键关闭。
4. **同质化**：打卡类产品极易被复制 → 护城河在**规则库 + 话术库 + 采纳数据**，不在界面。

**开放问题（需与试点机构确认）**
- 试点机构现有随访是护士做还是公卫做？决定工作台的角色模型。
- 是否能拿到脱敏历史数据做评测集？
- 是否接受"AI 生成内容必须医护确认"带来的延迟（患者可能等 2 小时）？
- 计费按"在管人数"还是"活跃人数"？（建议按在管，避免抑制录入）

### B.4 机构最常见的五个异议与回应

| 异议 | 回应（先给结论，再给证据） |
|---|---|
| 「我们已经在群里发了，不用系统」 | 群里发的是科普，不是任务。系统管的是「谁今天没做、谁做了异常、谁连续三天漏」，这三件群里看不出来。可以现场让对方打开自己群，问「昨天有几个人没打卡」，通常答不上来。 |
| 「护士没时间学新系统」 | 护士每天只用一个页面：今日待办。建档由患者自己填（微信带出姓名年龄），护士只确认。培训 2 小时，第二周就有肌肉记忆。 |
| 「患者都是老人，不会用」 | 老人不用装 App，微信里点一次就记住了。48 秒完成一次打卡，比打电话快。真正难的是第一次，所以 W3 全部现场建档，当面教一遍。 |
| 「AI 出错了谁负责」 | AI 不出患者可见的内容，只出草稿；患者看到的每一句都经过医生确认，页面上写的是「王医生已审核」。责任链在系统里可查。 |
| 「数据安全怎么办」 | 手机号加密存储、身份证号不采、报告原图存对象存储私有桶、导出留痕、家属权限逐项授权可撤。等保二级要求的最小集已覆盖，具体见第十章。 |

### B.5 退出标准（什么情况下应该停）

- 4 周内建档完成率 < 50% → 问题在名单质量或现场执行，不在产品，暂停扩量先修流程。
- 红灯 24h 处置率连续 2 周 < 70% → 机构没有配够人，产品不该背这个锅，写进结项报告。
- 医生审核一份报告平均 > 5 分钟 → 说明 AI 草稿质量不够或医生不信任，先冻结 AI-1，回到纯打卡。
- 3 个月内复诊转化无改善 → 说明复诊是院内流程问题（挂号、号源、交通），不是触达问题，重新评估收入模型。

## 附录 C：上线检查清单

**合规（缺一项不上线）**

- [ ] 产品内不存在任何开处方、改处方、推荐具体药品剂量的入口
- [ ] AI 输出全部落在「医护确认」之后，患者端不出现「AI 生成」字样
- [ ] 急救类关键词（胸痛、呼吸困难、意识改变、大出血）命中即固定跳 120 + 通知家属，不经过模型判断
- [ ] 知情同意逐次留痕、可撤回，撤回后停止一切主动触达
- [ ] 手机号等敏感字段加密存储，列表页只显示掩码
- [ ] 家属可见范围逐项授权（指标 / 报告 / 用药），默认全部关闭
- [ ] 数据导出、删除、更正三个动作都有入口且留痕
- [ ] 宣传材料不出现「替代就诊」「AI 诊断」「治愈率」等表述

**技术**

- [ ] 判级阈值、任务模板、响应时限全部可配置，且改动写审计日志
- [ ] 红灯判级只升不降；降级必须人工操作并填理由
- [ ] 消息频控生效：同类 24h 内 ≤1 条，免打扰时段只发红灯
- [ ] 打卡接口幂等（重复提交不产生重复记录）
- [ ] 微信模板消息 / 订阅消息失败有降级路径（转企微 → 转短信 → 转电话任务）
- [ ] 报告原图私有存储，URL 带时效签名
- [ ] 核心链路埋点全通（见附录 D），能独立回答「这个月活跃率是多少」

**运营**

- [ ] 机构侧有明确的责任田：谁负责哪些患者，写进系统而不是写在纸上
- [ ] 红灯升级链上每个人都知道自己什么时候会被叫到
- [ ] 每周一份周报自动发出（患者端 + 机构端各一份）
- [ ] 试点期每周一次 30 分钟复盘会，只看 B.2 那张表
