# 聊天录音音量波形设计

## 目标与边界

在 `/home` 和 Chat 的聊天输入框录音时，显示紧邻麦克风按钮的紧凑小柱波形，让用户能看出设备是否收到声音。只覆盖聊天输入框，不改入院 Demo 和独立语音识别页。

复用 `useVoiceInput` 已提供的本地音量回调，不新增 API、音频存储或权限请求。浏览器原生 `SpeechRecognition` 不向页面暴露音量数据，该路径保留现有录音状态提示，不显示伪造的音量波形。

## 方案与选择

1. **麦克风旁的音量小柱（采用）**：复用 RMS 音量回调，在现有输入操作栏内显示少量动态柱；占位小，并能真实反馈收音。
2. **输入框底部宽波形**：可见度更高，但会改变输入框高度与移动端布局，超出当前需求。
3. **麦克风按钮脉冲动画**：实现最简单，但无法区分真实收音和仅处于录音状态。

## 交互与数据流

- `useVoiceInput` 的 `onLevel` 将当前 RMS 音量传给 `ChatInput`，再传给 `ChatInputActionsRow`；显示更新按浏览器动画帧合并，避免每个音频处理块都触发整块输入框渲染。
- 小柱只在有本地录音流且 `recording` 为真时显示；柱高随归一化音量变化。静音时回落到低矮基线，停止、取消、错误收尾时归零并隐藏。
- 浏览器原生识别没有可用音量回调，因此不显示声波；现有识别状态和按钮提示保持不变。
- 波形是装饰性状态展示，标记为 `aria-hidden`；麦克风按钮继续提供可访问名称和焦点样式。

## 失败场景与验证

- 麦克风未授权、无输入设备或录音启动失败：不显示波形，沿用已有错误提示。
- 环境安静或麦克风输入为零：小柱回到基线，不显示虚假的活动强度。
- 用户松开实时按住说话、滑出按钮或取消指针：立即清零并隐藏；后续转写完成不重新显示。
- 服务端识别失败或超时：沿用 hook 的错误收尾，停止状态后波形清零。

定向测试覆盖：录音时波形可见且高度随音量变化；停止或不录音时隐藏；原生识别状态下没有音量数据时不生成波形。运行 Chat 输入操作栏测试、Dashboard TypeScript 检查、ESLint 和生产构建。真实麦克风强弱校准留给页面授权后的人工试音。
