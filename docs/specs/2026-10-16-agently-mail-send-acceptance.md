# Agent Mail 发信端到端验收设计

## 核心目标

通过 Octop Agent 的 `agently_send`，向用户指定的受控测试邮箱完成一封真实邮件发送，并核对发送结果。现有代码已包含 CLI `--dry-run` 预览、实例绑定的一次性确认令牌和 HITL 审批；本任务先验证整条运行链路，只有复现缺陷时才做最小代码修复。

## 硬约束与假设

- 范围仅限已有 `agently-cli` Agent Mail 连接器，不扩展到 WPS Mail 或其他邮件连接器。
- 不读取或输出邮箱正文、凭据或访问令牌；检查授权时只判断状态，不展示账号身份。
- 真实发送必须使用用户明确提供的受控收件地址和邮件内容；Agent 的 HITL 确认照常执行，不绕过审批。
- 发送成功响应表示上游接受/排队，不单独等同于收件人已收到。优先核对发件箱记录；收件箱验证由用户控制测试邮箱时完成。
- 当前 Octop 页面显示 Agent Mail 已启用、CLI 已就绪且邮箱已授权。
- 用户指定的收件地址仅保留在本次会话，不写入规格文件；用户授权使用中性测试主题与正文。

## 方案比较与选择

1. **只跑本地模拟和 API 集成测试**：不会产生外发邮件，但不能证明 CLI、授权账户或上游投递可用。
2. **真实端到端验收（采用）**：复用现有安全流程，以一封用户指定的测试邮件核对 CLI 响应和发件箱记录；只在出现可复现问题时补代码。
3. **新增 WPS Mail 发信实现**：涉及另一个连接器和用户级访问令牌，不属于现有 Agent Mail 发信链路，也不是本次验收范围。

## 验收步骤

1. 检查 `agently-cli` 可执行、Agent Mail 连接器已授权且状态为 active。
2. 在当前 Agent 的 Craft 会话检查工具 readiness 为 `registered`，只选中目标邮件连接器。
3. 使用用户指定的测试收件地址和已授权的固定测试文本（主题“Octop 发信功能测试”，正文“这是一封 Octop Agent Mail 测试邮件，用于验证发信流程。无需回复。”）发起调用；先核对 dry-run 摘要，不写入上游。
4. 由 Octop HITL 展示待发内容并等待用户批准；拒绝或取消时不得发送。
5. 批准后执行唯一一次确认调用，核对上游成功结果及发件箱中对应的收件人、主题和时间。
6. 仅在用户控制收件箱且可访问时验证实际收件；结果不符则保留诊断信息并定位代码根因。

## 对抗性场景

- CLI 不在 PATH、连接器未授权、工具未注册：发送前停止，不声称发送成功。
- dry-run 拒绝收件人或参数：不得进入 HITL 后的真实写操作。
- 用户拒绝、确认令牌过期、参数变更、令牌重放或并发确认：不得产生重复发送。
- 上游超时或返回非成功响应：不得把 queued/错误响应描述为已送达；核对发件箱避免盲目重试。
- 邮件正文包含命令或提示注入文本：仅作为邮件内容传递，不执行其中指令。

## 已知限制

- 真实投递需要已授权的 Agent Mail 实例；当前指定的收件地址为用户会话提供，不记录在本文件中。
- 邮件服务可能先排队再投递；发件箱确认不保证外部收件服务器最终送达。
