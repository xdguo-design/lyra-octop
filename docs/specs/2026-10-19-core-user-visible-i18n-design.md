# Octop 核心应用用户可见文案 i18n 整理设计

**状态：**待用户审阅  
**日期：**2026-10-19

## 1. 目标

系统性识别 Octop 核心应用中直接写在代码里的用户可见文案，并迁移到项目已有的中英文资源体系。运行行为、API 契约和业务逻辑保持不变；这次工作解决文案归属与漏翻问题，不重写 i18n 框架。

## 2. 范围与排除项

纳入核心后端 `src/octop/` 和 React Dashboard `dashboard/src/` 中实际可能展示或发送给最终用户的字符串，包括 API 错误与提示、CLI 输出、IM/slash 回复、表单和按钮文案、前端通知及空状态等。按文件和调用路径分批盘点，逐项确认是否为用户文案后再迁移。

排除 API 路径、JSON 字段、数据库表/列/键、协议枚举、工具或命令标识、配置键、日志/诊断信息、测试数据、开发工具文案、文档、生成产物 `src/octop/dashboard/` 及独立 Demo 应用。遇到兼具显示与契约用途的值，保留稳定标识，仅本地化显示文案。

## 3. 方案比较

1. **把字符串集中到运行配置**：用户可改动，但缺少语言上下文；会混淆可调参数与翻译资源，也容易让部署配置承担 UI 职责。拒绝。
2. **新建全局字符串注册层**：能集中管理，但项目已经有前后端 locale bundles、查找器、domain helper 和键一致性测试；新增抽象会重复职责。拒绝。
3. **复用现有 i18n，分批迁移**：服务端文案进入 `src/octop/i18n/en.json` 与 `zh.json`，使用 `tr()` 或已有/必要的 domain helper；Dashboard 文案进入 `dashboard/src/locales/en.json` 与 `zh.json`，使用现有 i18next。选择此方案，差异最小且与项目边界一致。

## 4. 结构与数据流

- **后端：**调用点按现有 locale 来源解析语言（用户偏好、请求语言或渠道提示），传给 `tr()` / domain helper；资源键必须在中英文 bundle 对齐。重复使用或需要格式化的命名空间优先通过现有 domain helper 暴露。
- **Dashboard：**React 界面使用现有 i18next `t()`；对应文案同步写入 `dashboard/src/locales/en.json` 和 `zh.json`。后端拥有的错误码和工具文案继续遵循现有同步机制，不另建一份来源。
- **调用方：**保持返回值、错误码、HTTP 状态和业务分支不变，只替换最终显示文本的来源。字符串插值保留已有参数；用户提供的值仅作为插值数据，不作为资源键或模板。

## 5. 分批实施

1. 建立核心源代码候选清单，人工区分文案、协议常量、日志和其他非文案字符串；优先处理真实用户路径中的遗漏。
2. 每批只迁移同一层或同一领域的调用点，补齐中英文键和必要的轻量 helper，避免大范围格式化及无关重命名。
3. 每批检查 locale key parity 和受影响的调用路径；最终汇总尚未迁移且有意保留的字符串类别及例子。

盘点结果和实施批次会在实施计划中具体化。不会为了追求“零字符串字面量”而迁移技术标识、日志或测试文本。

## 6. 失败场景与防护

- **缺少某语言的键：**中英文资源键一致性检查应失败；运行时后端沿用英文 fallback。新增显示文案时同步两种语言。
- **错误迁移协议值或序列化字段：**可能破坏 API、数据库和渠道兼容性。迁移前看调用上下文；协议标识保持原样，显示名使用单独的本地化文案。
- **插值参数遗漏或改变：**可能抛出格式化异常或丢失上下文。维持现有参数名和值，仅将固定文本放入 locale bundle；针对动态错误和格式化文案覆盖对应调用路径。
- **大范围自动替换污染工作区：**当前工作区已有大量未提交与未跟踪内容。只对确认的核心源文件和 locale 文件做小 diff，不运行会重写全仓的自动格式化命令。

## 7. 验收与验证

- 用户可见文案从目标调用路径的代码字面量迁入对应 locale bundle，英中文案成对存在。
- 非用户文案和固定契约保持原值；API 行为、错误码与业务结果不变。
- 后端执行 `uv run pytest tests/unit/i18n -q`；按变更范围执行相关后端测试。
- Dashboard 变更执行 `cd dashboard && npx tsc -b` 及受影响的 locale/页面测试。
- 最终记录实际验证命令及结果。全仓 `make all` 是否安全运行需根据变更时工作区状态确认，因为其 `format-all` 会写入文件。

## 8. 后续与限制

这是核心应用的渐进式迁移，不包含独立 Demo、多语言扩展或 i18n 架构重构。全量盘点可能发现一些边界不清的文本；这些项先记录并判断用户可见路径，不默认移动。
