# 入院登记页面感知语音处理设计

日期：2026-10-19。状态：用户已确认；代码与定向验证已完成。

## 目标

四个首页快捷项均为可操作按钮；按钮点击与语音转写进入同一页面意图分发器。语音转写后，按当时录音所在页面调用匹配的 AI 任务，并只执行该页面允许的下一步。首页不显示个人姓名、电话及账号操作栏；身份核验、表单和结果阶段保留原约定。

## 现状与约束

- `demos/admission-registration/frontend/src/logic/voiceFlow.js` 只在表单页调用候选字段提取；首页和身份页只显示转写。
- `demos/admission-registration/frontend/src/components/ConversationCard.vue` 四项都是 `<button>`，但前三项只显示功能提示，只有末项进入身份核验。
- Octop 的 `/api/admission-demo/extract` 使用当前已配置活动模型，通过 `page=1|2` 和固定提示词限制候选字段；目前没有按场景选择不同 Agent/模型的配置。
- Vue 表单实际调用 demo API `/api/admission-registration/v1/ai/candidates`，它要求有效 `identityToken` 后才代理到 Octop 提取接口，因此首页不能复用该入口。
- 表单候选由服务端白名单及原文校验；人工值优先。身份核验和提交均由现有明确控件与业务 API 控制。
- 录音开始时记录页面，异步完成时必须核对页面与 generation，避免切页后旧结果触发操作。

## 方案比较与选型

1. **页面专用任务路由（推荐）**：复用 Octop 当前活动模型，由服务端为首页意图和表单第 1 页、第 2 页使用不同固定任务提示词与结构化结果白名单。最少配置且兼容现有模型管理；“不同 AI”指不同页面任务，不声称使用不同底层模型。
2. **每页绑定独立 Agent/模型**：能切换底层能力，但需要新建配置、维护 Agent/模型标识、运行时可用性及管理 UI；当前 Octop 接口没有此映射，范围更大。
3. **前端规则识别**：不调用模型，可靠且成本低，但不能满足按页面调用 AI 的要求，也难以理解转写变体。

按最小配置选择方案 1。实现采用当前平台活动模型；不新增 Agent/模型映射配置。

## 页面动作

- **首页**：AI 可返回 `begin_admission`、`unsupported` 或 `unknown`。将“我要办理入院”“我要入院”“办理住院”“住院登记”及等价明确表达归一到首页第四个快捷按钮“可以说帮我入院登记”；只有明确识别该意图，前端才进入身份核验页。清楚请求挂号、打印、报告解读等当前未实现的功能时提示“当前页面没有这个功能”，不跳转；听不清、含糊、否定或无法理解时仍提示“未能识别”。
- **首页按钮**：四项都可点击。点击第四项直接调用相同的 `begin_admission` 页面动作；点击当前未实现的前三项，经同一分发器提示“当前页面没有这个功能”，不制造虚假目标页。按钮文案与语音语义使用同一意图定义。
- **身份核验页**：不调用 AI 执行页面动作；语音保留转写并显示静态刷卡提示。不得由模型签发身份令牌、调用核验成功路径或绕过“模拟刷卡”控件。
- **表单第 1/2 页**：继续调用现有页码白名单字段提取。仅把通过服务端校验的候选放入表单；不得自动翻页、提交或覆盖人工输入。
- **结果页**：当前没有语音区，不新增。

## API 契约

- 新增经 Octop `current_user` 认证的 `POST /api/admission-demo/intent`，请求 `{ "page": "home", "text": "…" }`，文本长度限制 1–2000 字符。
- 响应只含 `{ "intent": "begin_admission" | "unsupported" | "unknown" }`。服务端用当前活动模型和固定首页意图提示解析并验证枚举；模型不能返回前端事件名、URL 或自由格式指令。
- 首页按钮点击使用本地固定映射；所有 ASR 文本均调用该意图 API，由当前活动模型依据整句语义判断。提示词把“入院登记”“住院登记”“我要办理入院”“我想开始入院流程”等作为等义示例，并要求拒绝/取消表达返回 `unknown`。表单继续调用 demo API `/api/admission-registration/v1/ai/candidates`，通过身份令牌代理到现有 `/api/admission-demo/extract`；不改变字段白名单与候选验证。
- 超时、无效结构、越权字段和未知意图按 `unknown` 处理；明确但当前页不支持的请求按 `unsupported` 处理。

用户可见的操作结果由前端状态机处理，模型只能选择固定枚举，不能返回 URL、函数名、自由格式动作或业务 API 参数。ASR 模型调用超时、无效结构、页面变化时均不执行动作并显示“未能识别”；保留转写及可手动完成的路径。

## 数据与安全

一次请求只发送当前转写和页面任务，不带历史对话。请求长度有界；服务端固定提示词、固定动作/字段白名单。原始转写不得落盘。身份核验仍要求现有验证 API；最终提交仍要求表单校验和明确确认。AI 不决定资格、登记状态或医疗建议。

## 验收与对抗场景

- 首页“我要办理入院”“我要入院”“办理住院”“住院登记”进入身份页；明确的挂号、打印报告和报告解读请求提示“当前页面没有这个功能”；无关、含糊语音和模型超时提示“未能识别”，均不导航。
- 四个快捷项都可点击；第四项进入身份页，前三项提示“当前页面没有这个功能”，无异常、无虚构页面。
- 身份页语音不能改变认证/提交状态；任何时候都需现有模拟刷卡控件和最终确认路径。
- 第 1 页长句不能填第 2 页字段，第 2 页也不能填第 1 页字段；歧义候选不覆盖人工值。
- 录音后页面被切换或会话重置，迟到 AI 响应不能触发旧页面动作。
- 畸形 JSON、越权字段、未知动作、提示注入、超长文本、并发连续录音和请求超时均安全降级并保留转写。
- 初始首页不呈现账号用户栏；身份核验、表单及结果页行为符合既有规则。

## 实施范围

只改入院登记 Vue 前端、Octop 入院意图 endpoint/服务提示词与其测试、原型说明和 `memory.md`。不新增底层模型配置、Agent 管理 UI、语音供应商、医院接口或真实身份/登记能力。首页意图使用当前活动模型；表单继续使用既有字段提取任务；不实现前三项尚无目标页或 API 的医院业务。
