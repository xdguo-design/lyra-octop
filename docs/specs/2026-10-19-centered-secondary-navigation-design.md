# 居中二级导航设计

**状态：** 草案，等待用户审阅  
**日期：** 2026-10-19

## 1. 问题拆解

### 目标

统一 Octop/LYRA 的二级导航呈现方式，参考用户提供的 WorkBuddy 截图：二级导航以居中、带分组侧栏的面板打开，避免同一层级有时从右侧抽屉打开、有时占用整个主页面，导致导航层级不清楚。

### 范围与约束

- 覆盖 LYRA 侧栏“更多”弹出菜单中的二级导航目标，以及头像菜单中的个人设置入口。当前路径集合为 `/token-usage`、`/personalization/*`、`/connectors`、`/skill-packages`、`/bridge`、`/acp` 和 `/admin/{models,users,backend,plugins,security,advanced}`；菜单仍由现有权限和动态导航数据决定，不复制静态目录。
- `/admission-demo` 虽从“更多”可达，但它是由外层应用路由承载的独立全屏 Demo，不属于二级导航页；保留当前独立页面、认证与返回行为，不嵌入菜单面板。
- 主产品入口优先：对话、Agent、任务、电脑、创作、资料库维持主页面行为，即使同一导航项也存在于设置数据分组中。
- `/workbench*` 保持全屏 keep-alive 工作区，不能塞入二级菜单面板。
- 二级面板采用左侧分组导航、右侧内容的布局；桌面居中浮层，移动端使用全屏面板。
- 保留现有 URL、查询参数、权限校验、页面组件和深链能力。
- 新增、编辑、确认等短流程弹窗不纳入导航改造；这类表单继续按其操作语境使用居中对话框或已有抽屉。
- 头像菜单本身继续锚定头像弹出；个人设置打开居中面板；修改密码继续作为短操作对话框。

### 假设

- 用户所说的“所有二级菜单”指二级导航页面，而不是页面中的每一个新增/编辑表单。
- 浏览器直达二级路由时显示同一面板，并以 `/home` 为背景。
- 面板导航基于现有路径；返回/前进和关闭规则固定如下，不依赖运行时试选。

### 失败模式与防护

1. 直接访问深链时缺少背景页面：用 `/home` 作为背景，不渲染空壳；关闭后以 replace 导航回 `/home`。
2. 面板切换后 URL 与选中项不一致：以路由作为当前选择的唯一来源，覆盖刷新、复制链接、浏览器返回/前进。
3. 权限变化或低权限用户打开管理员深链：复用现有路由权限守卫；面板导航只展示用户有权访问的项目，不作为授权边界。
4. 长表单或宽表格挤在小面板：桌面面板使用接近视口的最大宽高并在内容区内部滚动；移动端全屏显示，避免嵌套横向滚动。
5. Escape、遮罩点击或浏览器返回导致未保存编辑丢失：路由面板内导航遵从页面已有保存行为；个人设置表单 dirty 时，关闭或切换前弹出确认，不静默丢弃。

## 2. 方案对比与选型

| 方案 | 做法 | 收益 | 成本/风险 |
|---|---|---|---|
| A（推荐） | 保留路由和现有页面组件，给二级导航加统一的居中面板壳；页面内容在壳内切换 | URL、权限、深链和页面逻辑保持；统一导航呈现 | 需梳理页面容器高度、滚动与面板关闭历史 |
| B | 把所有二级页面重新做成侧栏内嵌工作区 | 视觉连续，无浮层遮罩 | 主工作区会被替换，仍接近“当主页面使用”；导航层级问题没有彻底解决 |
| C | 只统一个人设置和管理员设置，其余二级页保持现状 | 改动较少 | 设置、连接器、技能、远程控制等继续使用不同层级，不符合“二级菜单都弹出”的目标 |

**选择 A。** 现有页面已经由路由、权限守卫和独立页面组件管理；新增一个呈现层比迁移业务页面更简单，同时满足统一居中弹出和保持深链的要求。

## 3. 交互与布局

### 面板结构

- 桌面端：居中 modal-style panel，最大宽度约为视口宽度的 92%、最大高度约为视口高度的 92%；圆角、遮罩、右上角关闭按钮。
- 左栏：搜索框与分组列表，分组沿用现有“设置 / 管理 / 控制”导航定义；当前项目使用清晰选中态。
- 右栏：渲染现有二级页面组件，不复制业务逻辑；内容区独立滚动，面板标题显示当前页面名与所属分组。
- 移动端：全屏两阶段显示，先显示分组目录，选中后显示内容；内容页提供返回目录和关闭操作。
- 从应用内主页面打开二级目标时 push 一条面板路由；关闭图标、遮罩点击、Escape 或浏览器 Back 回到打开面板前的页面。
- 面板内切换二级目标时 replace 当前面板路由，避免 Back 逐项倒退；浏览器 Back 关闭面板，Forward 重新打开最后一个二级目标。
- 刷新或外部直达二级深链时保留该 URL、query 和 hash，并以 `/home` 为背景；关闭时 replace 到 `/home`。深链刷新后 Back 遵从浏览器原有历史，不额外伪造应用内来源。
- 旧别名继续走现有 redirect 规则；本次不改变各别名对 query/hash 的既有保留行为。面板导航列表只使用当前 canonical 路径。

### 入口与层级

- 侧栏顶级产品入口和 `/admission-demo` 独立应用入口维持当前主页面行为。
- “更多”与账号头像继续显示紧邻触发器的轻量菜单；点击其中的二级导航目标后打开居中面板。路由面板数据取自现有动态导航目录和权限过滤；各页面继续使用目前已有的认证与路由守卫。
- 次级导航页面之间切换时复用同一面板，不叠加多个抽屉或 Modal。
- 页面内的新增/编辑表单保持其现有操作层级，不纳入全站导航面板。
- 头像菜单中的个人设置使用本地状态打开居中个人资料面板，不新增 URL；刷新时不保留未提交编辑，dirty 状态关闭或切换时要求确认。修改密码保留独立短操作对话框。

## 4. 实施边界

- 主要涉及 `dashboard/src/layouts/Sidebar.tsx`、`dashboard/src/layouts/sidebarNav.tsx`、`dashboard/src/components/AvatarDropdown.tsx`、`dashboard/src/layouts/MainLayout/` 与路由状态处理。
- 保持 `dashboard/src/routes/index.tsx` 中的路由地址和页面模块，增加统一的二级导航容器/面板路由呈现；`/admission-demo` 继续由 `dashboard/src/App.tsx` 的外层认证路由独立渲染。
- 不修改后端 API、数据库、权限模型、导航数据权限过滤规则。
- 每个页面保留目前已有的认证与路由权限守卫；面板不复制或替代 `AuthGuard` / `RequirePermission`。
- 不将工作台、对话、Agent、任务、电脑、资料库、创作等主产品入口改成弹窗。
- 不把业务页面中的创建/编辑表单改为全局面板。

## 5. 对抗性验证设计

- 用每个分组各一个路由验证入口、切页、选中态、关闭、刷新、复制链接、浏览器前进/后退。
- 直接访问 `/admin/models?tab=voice`、`/personalization/channels` 等带参数/子路由，确认面板和原页面内容一致；验证 query/hash 保留。
- 用普通用户访问管理员深链，确认现有权限拒绝仍生效且不泄漏页面内容。
- 页面长内容与宽表格在桌面和窄屏下检查滚动、裁切、横向溢出及关闭按钮可达性。
- 个人设置 dirty 时测试关闭/Escape/遮罩点击，确认询问后再关闭；验证修改密码对话框仍正常工作。
- 二级面板切换时检查不会重复挂载多个 Drawer/Modal，也不会让背景页面继续接收非预期操作。
- 验证对话框语义、焦点陷阱与关闭后的焦点恢复、背景不可交互、页面滚动锁及全键盘可达。
- 验证主产品入口（含 `/workbench*` keep-alive 工作区）没有被路由面板包装。

## 6. 验收标准

1. 当前“更多”菜单中列出的二级导航目标均通过同一居中二级导航面板打开；主产品入口与 `/admission-demo` 独立全屏应用保持原行为。
2. 一级功能页仍以主页面打开；新增/编辑等操作表单保持原有交互。
3. URL、查询参数、权限校验和刷新/前进/后退行为保持有效。
4. 桌面布局层级接近 WorkBuddy 图三，账号入口菜单维持图二的轻量弹出风格。
5. 移动端采用“目录 → 内容”两阶段全屏切换，关闭和导航操作可触达。
6. 面板导航、权限、URL 历史、query/hash、键盘焦点与遮罩交互符合本设计约定。

## 7. 本设计不包含

- 将主产品功能改为弹窗或搬入设置中心。
- 把页面内创建/编辑业务表单统一转换成二级导航面板。
- 修改后端权限、导航项授权、API、数据库或 legacy URL 重定向语义。
