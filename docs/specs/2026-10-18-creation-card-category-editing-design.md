# 创作卡片分类可编辑设计

## 问题与目标

内置卡片的分类目前固定在前端定义中，用户无法纠正“平台 / 应用（小程序）”归类。目标是在现有卡片编辑弹窗中允许用户修改分类，并在刷新后保留。

## 方案

在内置卡片编辑弹窗增加“平台”“应用 / 小程序”“网站 / 服务”和“代码仓库”选择项。通过现有每用户卡片元数据 API 持久化分类，并在创作列表构建时优先使用用户分类；没有用户设置时沿用代码中的默认分类。数据库为 `creation_card_meta` 增加可空分类字段，并校验四种受支持分类。

分类只控制创作页的分类筛选与展示归类；内置 Demo 的应用类型、路由和打开行为保持不变。普通创作条目和网站 / 服务的编辑方式不变。

## 备选方案

- 将内置 Demo 转为普通创作记录：会产生重复卡片并改变既有入口，维护成本更高。
- 只在浏览器本地保存选择：换设备或清理浏览器数据后丢失，不能复用现有账号数据模型。

因此使用账户级元数据保存分类。

## 失败场景与防护

- 用户没有自定义分类：返回 `null` 并回退至内置默认值。
- 非法分类值被提交：API 的 Literal 校验及数据库 CHECK 约束拒绝；已有卡片元数据通过迁移保留。
- 用户把 Demo 分类改为平台后打不开：运行时应用类型和路由独立于展示分类，不受分类值影响。

## 验收

- 在卡片编辑弹窗切换四种分类之一并保存，刷新后仍显示于所选分类筛选结果。
- 分类变更不影响 Demo 卡片打开 `/admission-demo`。
- 旧的内置卡片元数据可继续读取和编辑。
