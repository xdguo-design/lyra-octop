# 入院登记页面与患者对话改版设计

日期：2026-10-19。状态：用户已确认，待按关联实施计划执行。

## 1. 目标、约束和事实

用户提供的五屏总图作为新视觉基准，第二张身份认证对话图作为底部语音栏和对话样式基准。用户已澄清：必须存在本人有效入院申请单，申请单展示入院科室、入院时间等信息，才能办理入院。此次涉及三个关联部分：页面与交互、申请单办理流程、患者对话与结构化上下文。

沿用 `demos/admission-registration/` 的 Vue 2 + Element UI 和 FastAPI，不切换框架；ASR/TTS 沿用 Octop，模型继续使用已选的 Qwen。修改当前创作页实际打开的 Vue 应用，不把旧 React Demo 当成已交付的当前页面。医院身份、申请单、字典、提交仍使用明确标示的 mock。

最新明确需求覆盖旧决定中的“只使用本轮转写、不保存患者上下文”和“没有申请单页”。用户已确认新增独立信息确认页，以及仅在当前确认页版本有效、无待确认修改时接受明确语音提交。实施时同步更新旧 PRD、页面规格与 memory，避免相反规范同时有效。

基本原则：身份由认证结果确定，申请单由业务数据确定，表单当前有效值由服务端校验后的结构化状态确定。模型只提供语义解析及受约束的提问，不成为这些数据的权威来源。

## 3. 方案对比与选择

1. **采用：保留 Vue/Element UI，重做视图组件，增加一个服务端会话协调模块。** 复用现有地区、字段验证、ASR/TTS、模型连接、认证、数据库和幂等提交。收益是把表单、对话、确认统一到同一个可信状态，且只改入院应用相关范围。
2. 仅换 CSS 并在前端累加聊天数组。视觉工作少，但无法正确完成重启后的结构化存储、版本冲突、申请单复核和跨患者隔离，不能满足本次要求。
3. 整体迁移 React 并引入通用 Agent/向量库。可复用平台外观，但迁移和数据映射更大；本次表单是有界任务，关系数据库与有限上下文即可完成，不需要额外记忆服务。

## 4. 页面与申请单流程

流程：AI 首页 → 身份认证 → 本人入院申请单 → 基本信息 → 补充信息 → 信息确认 → 提交中/结果。

### 4.1 视觉和布局

- 采用新参考图的浅蓝白底、深蓝标题、蓝色主操作、轻边框和一致圆角；减少厚重阴影、重复提示条和空白区域。机器人首页较大，业务页缩为引导角色，不占据表单主要区域。
- 顶部统一品牌、帮助和当前步骤。业务内容、主操作、底部语音栏有明确分区。主操作和语音入口固定可见，不与患者信息条挤成一行。
- 表单分页控制高度，保证常用终端视口无整页滚动条；短视口/大字体下允许内容区触控滚动且不显示滚动条，不能为隐藏滚动条而裁掉字段。对话记录在弹窗内部滚动，正文不被撑高。
- 首页只显示已有业务入口；挂号、报告等入口继续明确提示未实现。首页不显示上一位患者身份。
- 当前人姓名/电话以紧凑摘要展示，不换行挤压“变更/退出”按钮；未认证时完全隐藏。

### 4.2 申请单是强制前置条件

- 认证成功后，根据服务端认证患者标识查询本人申请单，禁止客户端用任意姓名/证件号查询患者。
- 页面展示申请号、患者脱敏姓名、入院科室、计划入院时间、开单医生、开单时间、住院类型、诊断、病区、申请状态。医院未提供的可选信息显示“未提供”；不让 AI 补造。入院科室、计划入院时间及有效状态为本次演示申请单必备项；时间按服务端医院时区格式化。
- 多张有效申请单：展示可选择列表，只能选一张，并明确确认。只有一张也须确认。取消、过期、已使用、其他患者的申请单不可进入下一步；无单/查询失败保留身份阶段提示并提供重试/现场帮助。
- 表单会话固定绑定 `owner + patient + application`；更换患者或申请单会清理对应草稿、提案和上下文，并重新认证/确认。
- 提交时重新检查本人身份、申请单归属/有效性、当前表单版本及最终确认版本。申请单过期或已使用时即使前端曾显示有效，也不能办理。
- 展示与查询接口、提交验证必须一起实现；只增加一张静态卡片不算完成。

### 4.3 表单与最终核对

保留已有14项合同作为现有业务基础。新视觉图出现但当前合同没有的字段单独核对，不能把装饰示例误当作真实档案值：性别、出生日期若由核验资料提供则只读展示；入院科室、入院时间、诊断等从申请单只读带入；医保类型、就诊类别等只能来自申请单/医院字典；普通联系人姓名/电话/关系和紧急联系人电话需有对应合同与 mock 才能加入录入。不得只在 UI 新增输入而遗漏后端、验证和最终确认。

本轮设计默认保留现有14项录入必填规则，新增申请单展示，不擅自把参考图额外字段都改为必填。额外字段显示/采集以本段来源约束为准；无数据且无合同的控件不显示。医院真实字段扩展另按实际合同确定。

新增最终核对页，包含全部实际采集字段和所选申请单摘要，长内容分组“展开更多”。点击编辑回到对应表单并保留其他信息。核对页显示的值必须直接读当前快照；缺失必填项、未决修改或无效身份/申请单阻止确认。

## 5. 语音栏与 AI 对话弹窗

### 5.1 真实波形和操作状态

- 底部采用图2：左侧大麦克风，中间波形与操作说明，右侧“手动输入”。支持按住说话、松开发送；键盘/辅助操作另提供明确的开始/结束开关。图示波形不能用随机动画假装检测到声音。
- 状态为 idle、申请麦克风、录音静音、录音有声、转写中、AI理解中、AI播报、错误。录音静音时仍显示低幅稳定波形及“正在听，等待您说话”；检测有声后显示随音量变化的蓝色波形及“正在收音”。识别/理解中停止音量动画，显示处理状态。
- 用同一 `MediaStream` 接入 Web Audio `AnalyserNode`，根据 RMS 和连续帧门槛区分声音/静音，避免阈值附近抖动；音量不上传、不单独存储。停止、取消、异常、离页释放轨道、分析器、动画帧和 AudioContext。
- 移动端支持 pointer capture、pointer cancel 和滑出取消；避免一次点击同时触发按住与切换两条录音路径。单次上限沿用60秒；空音频不请求模型；权限拒绝展示可操作提示。

### 5.2 对话辅助

打开“语音录入”后显示对话弹窗/大屏侧面板，呈现“AI提问—患者回答—字段回填结果”。一轮只有一个主要动作，但患者主动说多个字段时全部提取并验证，不丢弃其他字段。

对话面板保留同一底部语音栏和文字输入入口；关闭面板只是退出辅助录入，不清空表单。修改确认优先显示为对话面板中的明确确认卡，包含字段、原值、新值和按钮；语音同意/拒绝与按钮进入相同服务端操作，避免重叠多个模态弹窗。

问题由服务端当前缺项决定，每轮最多追问一个最关键必填字段。已有有效档案值或已确认值不重复询问。枚举以真正的选项按钮/控件呈现；用户只说“已婚”“配偶”“跟上面一样”时，依据当前问题和明确指代解析。无唯一指代时追问，不复制猜测。

ASR文本可编辑；ASR识别不确定、格式不合法或地区只到城市时保留原话/候选并要求补充，不凭空补区县。录音前停止TTS，播报时不自动收音，避免模型自问自答。

## 6. AI 上下文、存储与修改规则

### 6.1 双链含义和最小存储

这里把“双链存储”定义为**对话记录链 + 结构化事实链，并可双向追溯**，不引入区块链、向量库或平台所有 Agent 共享记忆。

复用平台 SQLite/PostgreSQL 与 repo/service 分层，新增两类持久数据：

1. 办理会话快照：归属用户、认证患者的内部引用、申请单引用、阶段、`revision`、当前字段及每项来源/确认状态/`source_turn_id`、待确认修改、待回答问题、格式化摘要、`last_turn_id`、到期时间。保存真实字段值只在认证后，身份证等只读信息优先引用认证快照，避免重复复制。
2. 追加式交互记录：`session_id + turn_id + previous_turn_id`、角色对应的患者原话/AI回复、动作类别、候选和校验结果、已确认变更的旧值/新值、来源轮次、处理状态和时间。当前事实指向来源轮次，每轮交互保存影响的字段，形成双向关联。

当前值和重要信息以机器可读JSON保存，不用一段摘要文字替代；最后一次交互单独通过 `last_turn_id` 和状态定位。事实快照、变更记录、最后交互指针在同一数据库事务提交，防止日志显示已修改而表单仍旧值。

收到转写后先保存本轮输入与 `processing` 状态，再在事务外调用模型；完成时将回复、事实变更及最新交互指针一起提交。已经完成的轮次不改写原话，修正以新事件记录；处理中的轮次只允许完成/中断等生命周期更新。服务重启后未完成轮次标记中断并保留原话，用户主动重试沿用该轮幂等标识，不自动补发模型请求。手工编辑和按钮确认也记录对应操作事件及字段来源。

### 6.2 修改与并发

- 补充空字段：验证后写入当前快照，显示回填结果与来源。
- 改动已有确认值：先存修改提案，不改有效值；用户点击或语音明确确认后，比较提案的字段旧值和会话版本，再原子替换该字段。拒绝则丢弃提案。
- 用户直接手动编辑表单属于明确修改动作，保存后更新版本与来源；旧的语音提案不能覆盖此后的手动修改。
- 确认后旧值仅留在受权限限制的变更记录中；当前事实、摘要和下一次模型输入立即使用新值。一次提交最多一个生效轮次，同一 `turn_id` 重试不重复写日志/改字段。
- 模型请求在事务外执行，返回后按 session/patient/application/revision 重新核对；用户换人、退出或编辑后，迟到结果不回填。人工操作和模型回填共用同一更新入口。

### 6.3 上下文预算

每次请求按固定结构组装：系统任务与动作白名单 → 当前认证/申请单阶段摘要 → 当前有效字段与缺项 → 待回答问题/待确认提案 → 最近4轮交互 → 当前输入。最后一轮已包含在窗口内时不重复注入。

目标输入预算6000 tokens，预留输出1200 tokens。超限先减少历史轮次/附加文字，始终保留系统规则、当前结构化事实、当前问题和本轮输入；关键部分仍超限则明确要求缩短输入，不静默截掉姓名/地址等值。不把所有地区节点或整段历史塞入 prompt；只提供允许的枚举及候选地区路径。

格式化摘要由当前事实和未完成任务生成，不使用旧对话总结重新推断事实；更新字段时重建对应摘要，防止已纠正的地址从旧摘要“复活”。历史原话属于非可信数据，不能覆盖规则、申请单或字段来源。

### 6.4 受控模型输出和调用次数

一轮模型调用同时完成当前输入的语义类别、字段提取、指代解析和确认意图，返回固定JSON。服务端验证允许动作、来源、字段、枚举、地区路径及当前版本后再执行。模型不能直接调用任意页面元素、查询其他患者或写数据库；UI按受控动作渲染/导航。

一轮优先完成“修改确认”等当前主要动作；用户同时谈其他事时不把“好的”误作提交。下一问题由缺项控制器确定，不另外调用一次模型生成问题。已选Qwen保持不思考和不自动重试429。

AI确认提交仅在最终确认页、当前版本已展示、无未决修改且用户明确表达提交时产生受控提交意图；服务端执行最终身份/申请单/全表验证并使用同一幂等键。此项是对旧“语音只能填字段”边界的提议扩展，须随本设计确认；任何其他阶段的“确定”均不能提交。

429明确显示限流，有 `Retry-After` 时显示等待时间；超时、连接失败、格式无效、语义不明分别提示。错误保留转写和草稿，提供主动重试，避免重复录音/多次模型调用。请求/错误日志记录脱敏元数据和关联ID，不打印完整患者原话。

### 6.5 隔离、归档和清理

未认证的首页交互只属于临时匿名会话，不能关联或读取患者历史。认证后存储以当前Octop用户、患者及办理会话共同授权，客户端无法指定其他患者ID；本次新会话不自动从该患者旧办理历史回填。

归档的患者标识使用服务端认证来源提供的稳定内部引用；认证有效期和授权会话与归档分开管理。Bearer凭证、麦克风录音和可复用身份令牌不写入对话归档，恢复展示必须重新核验，不能把数据库里的患者引用当作仍有权限。

退出/完成/超时立即清除终端可见数据并终止活动会话。用户本次要求保留对话，故与旧“不落盘”约束不同：草案默认演示归档在服务端保留24小时后清理，包含原话、事实和修改记录，不持久保存录音；退出后的归档不允许终端直接恢复，必须重新核验身份。若接真实医院，保留期限与访问角色须按院方要求替换，不能把演示期限宣称为生产规范。

## 7. 代码与配置影响范围

- Vue `App.vue`保留页面组合与导航，拆出申请单、信息核对、对话面板、语音栏组件；把当前voiceFlow中的录音/播放生命周期与对话业务协调分开。只拆实际过大的职责，不做全仓重构。
- `VoiceRecorder`增加真实音量事件和完整释放；复用WAV转换、地区数据、字段合同、键盘及现有UI组件。
- 服务端在 `infra/`负责申请单、会话、上下文、提案和最终提交策略；`api/`只做认证、schema和错误映射。repo只负责SQL；更新 `SharedServices`、成对SQL迁移、schema版本测试和API文档。
- Octop托管与独立Demo后端共用合同与语义规则，补齐对应路由、mock和测试，避免同一前端两种运行方式表现不同。独立模式仍要求平台认证代理，不新增患者密码。
- 更新Demo README、接口交接、PRD、页面规格、验收和新缺口记录。复用现有依赖声明、配置与发布构建，不因视图改版新增无必要Docker/CI或依赖。

## 8. 对抗验证与交付标准

| 真实失败场景 | 防护和验证 |
| --- | --- |
| 无单、过期单、其他人单、多单误选、提交前单已撤销 | 所有查询/选择/提交按认证患者复验；API用例覆盖不得进入/不得提交，不把模型回复当有效申请单 |
| “地址改了”后旧AI响应晚到，或两个窗口同时修改 | 会话revision/提案快照CAS；模拟反序返回、重复turn、手动编辑插入；旧值不能恢复 |
| 患者A退出时录音、身份查询或AI仍在跑，患者B开始 | 前后端会话标识+撤销；迟到回调不显示A的信息、不挂到B的会话 |
| 静音显示假动画、拒绝权限、按住后滑出、重复点击 | 合成静音/声音音频驱动meter和状态测试；确认轨道/RAF/AudioContext全释放，真实麦克风另验收 |
| 用户说“已婚”“也住那里”“不要改”“确定” | 针对当前问题和提案的模型协议fake回归；未知指代追问，否定不写入，非核对阶段不提交 |
| 长句跨页多字段，模型返回非法字段或提示注入 | 全任务白名单、来源链、JSON约束、字段校验；身份/申请单/系统规则不能被输入覆盖 |
| 第5/第20轮后上下文膨胀，修改旧值后被摘要恢复 | 断言预算裁剪、当前事实优先、最后交互不重复、摘要更新；不依赖无限聊天历史 |
| 429、超时、TTS回音、重试重复提交 | 明确错误+保留草稿；无自动重试风暴；录音停播报；相同turn和业务幂等键不重复执行 |
| 服务重启后快照/最后交互/历史不一致，归档泄露 | 事务和重启恢复测试；用户/患者隔离、过期清理、原文不进入普通日志，归档重新认证后才可访问 |

验证分层：共享字段与上下文单测 → 两套Demo/API集成 → Vue组件/全流程回归 → TypeScript/Ruff/构建 → 浏览器真实点击和不同终端高度目视。浏览器至少走首页、认证、申请单、两页表单、核对、修改确认和结果，不用jsdom结果替代真实布局/按住交互验证。真实麦克风和Qwen只做少量预先列出的合成样例，顺序执行，不再连续轰击模型；无法完成的硬件/HIS验证必须标明。

运行命令沿用仓库：`uv run pytest`的入院相关文件；Demo frontend下`npm run test -- --run`、`npm run typecheck`、`npm run build:dashboard`；Python定向Ruff；全仓`make all`若触及其他任务未提交文件，先说明并采用不改写其他文件的对应检查。本设计阶段不跑模型、不改业务代码。

## 9. 已确认的实施基线

实施按以下基线：本人有效入院申请单是服务端强门槛；保留14项现有录入合同并按可信来源补展示字段；增加独立核对页；真实音量波形；双向关联的对话/事实存储及24小时演示归档；最终核对页允许明确语音确认经业务校验后提交。真实医院/HIS仍不在本 Demo 范围。
