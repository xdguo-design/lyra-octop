# 工作台小程序与 PPT 创作入口设计

## 问题拆解

- **目标：** 在侧栏「创作」对应的工作台首页提供小程序和 PPT 的创作入口；用户选择具体任务后，将引导描述交给当前专家处理。
- **约束：** 复用 `WorkbenchHome` 的首页卡片与 `onSubmitTask` 通路；界面文案支持中英文；保留已有星球乐园、工作流和浏览器入口。
- **假设：** 用户选择的“进入对话”对应当前工作台右侧 AI 助手面板。当前 `handleSubmitTask` 会打开该面板并提交任务，不跳到 `/chat`。任务能否生成可用成果，取决于当前专家及其工具。
- **失败模式：** 卡片点选没有交付任务、任务描述只给出空泛目标、卡片挤占已有工作台功能、英文环境漏出中文文案、窄屏任务选项无法使用。

## 方案对比与选型

1. **卡片 → 任务选择器 → 当前 AI 助手（选用）**：增加小程序和 PPT 两张工作台卡片；选择卡片后显示该类任务模板，选中模板后用现有 `onSubmitTask` 打开右侧 AI 助手并传入引导描述。无需新 API、数据库表或生成服务。
2. **小程序/PPT 独立制作页面**：引入专用编辑器与生成流程。当前仓库没有这两类成果的独立编辑能力，建设成本和范围都超出本次入口需求。

首页现有「更多工作台」是不可点击的占位卡。用两张创作卡替换该占位卡，保留星球乐园、工作流和直接启动浏览器的入口。

## 交互与数据流

1. 首页显示「制作小程序」和「创建 PPT」卡片。
2. 点击任一卡片，打开任务选择对话框；小程序示例包含商城、预约/报名、互动游戏，PPT 示例包含产品介绍、工作汇报、方案提案。
3. 点击具体任务后，关闭选择器并调用 `onSubmitTask(prompt)`。提示词说明期望先确认关键信息，再产出可预览或可交付的内容；不承诺 Octop 本身提供独立编辑器。
4. `Control/RemoteBrowser/index.tsx` 已将 `onSubmitTask` 接到当前专家的右侧 AI 助手面板。无需新增路由、持久化或后端接口。
5. 任务选择器、卡片标题、描述和提示词均通过 `workbench.home` 的中英文翻译键提供。

## 对抗性验证设计

- 点小程序与 PPT 卡片后，分别验证只显示对应任务；选中一种任务后验证准确调用一次 `onSubmitTask`。
- 关闭任务选择器或点击遮罩/取消时不提交任务；重复点击不会发送两次。
- 所有新文案在中英文资源里都有对应键；任务卡在窄屏下可读且可点击。
- 验证既有星球乐园、工作流、发送输入和启动浏览器交互保持可用。

建议验证：`cd dashboard && npx vitest run src/pages/Control/RemoteBrowser/WorkbenchHome.test.tsx`，以及 `cd dashboard && npx tsc -b`。按项目约定，此次设计文档阶段不运行测试。

## 已知限制

- 入口只负责把任务交给当前专家；成果形式、质量和文件导出能力由专家及其工具决定。
- 示例任务先作为前端固定模板维护，不新增模板管理或创作记录功能。
