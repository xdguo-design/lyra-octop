# `/connectors` 统一资源页设计

## 1. 问题拆解

### 核心目标

在 `/connectors` 中把专家（角色）、技能、连接器放进一个可搜索的资源列表。用户不必在三个独立页面间切换；搜索覆盖三类资源，已安装、已导入或已启用的资源优先展示。

### 硬约束与假设

- 目标是截图中的 `/connectors` 页面。当前仓库该路由是连接器配置页；专家和技能的现有市场在其他路由。
- 只合并专家、技能、连接器。插件不纳入本次统一列表，仍走现有插件管理入口。
- 保留现有资源动作：专家进入创建/管理流程，技能先预览再导入技能包，连接器继续配置、编辑和管理实例。
- “已启用优先”按用户确认的现有状态判定：专家已装入其任一 Agent；技能已导入任一其可访问的技能包；连接器实例状态为 active 且已有凭据。
- 仅请求用户具有权限访问的资源目录；某一目录失败时仍显示其他成功加载的类别。

### 失败模式

- 搜索只查当前类别，用户误以为其他资源不存在。
- 混合排序后已启用资源被未启用资源穿插，或搜索时已启用项状态丢失。
- 资源类型之间 ID 冲突导致 React key 或点击动作串项。
- 某类别 API 失败导致整页空白。
- 技能导入状态用逐包请求计算，包数量变多后产生 N+1 请求和加载延迟。
- 将凭据、token 或完整连接器配置意外展示在卡片或搜索索引中。

## 2. 方案对比与选型

| 方案 | 交互 | 优点 | 代价 |
|---|---|---|---|
| A. 单一混合列表（采用） | 一张卡片网格，顶端统一搜索；“全部 / 专家 / 技能 / 连接器”作为可选筛选 | 真正跨类别搜索；启用项可全局置顶；匹配用户的“放一起” | 卡片需显示类型和状态，管理入口需保留 |
| B. 同页分三块 | 搜索后分别显示专家、技能、连接器区块 | 类别边界清楚 | 每块都要滚动；无法实现全局已启用排序 |
| C. 保留三张标签页 | 标签页之间共享搜索框和排序规则 | 改动最小 | 仍需手动切换，未解决主要不便 |

采用 A。用户提出合并浏览并要求已启用优先，单一列表是能同时满足这两点的最简单交互。类型筛选只是可选缩小范围，不承担页面导航。

## 3. 页面与数据行为

- 顶部固定资源类型筛选和一个跨类别搜索框。筛选默认“全部”；支持专家、技能、连接器。
- 搜索名称、简介及类别，按当前语言做大小写不敏感匹配；类型筛选和搜索可以组合。
- 结果先按“已启用/已导入”分组，组内保持目录返回顺序，避免每次渲染随机跳动。卡片显示类型和可读状态。
- 移除重复的“精选资源”区，避免同一资源出现两次并干扰已启用项置顶。
- 专家状态沿用现有安装识别：当前用户拥有的 Agent 中已有相同专家模板/ID，即标为已安装。卡片继续进入专家创建/管理流程。
- 技能状态通过当前用户可访问的技能包中的 slug 匹配目录条目。为避免对每个技能包分别请求，增加一个只读聚合 API，按现有 `skill_packages` 权限返回可见包中的技能 slug 集合；不返回技能正文或凭据。导入流程仍使用现有预览、目标包选择和确认操作。
- 连接器状态沿用现有实例：目录条目存在 `active` 且 `has_credentials` 的实例即为已启用；已配置连接器保留编辑/禁用入口，目录条目保留配置入口。自定义 MCP 继续可见并保留现有管理操作。
- 只加载用户有权限访问的类别。若单类读取失败，在该类别区域显示可重试错误；其他类别照常可用。

## 4. 安全与边界

- 不改变服务端权限、连接器凭据存储、专家安装、技能导入或连接器执行逻辑。
- 聚合技能状态 API 仅返回授权用户可见的 skill slug，不读取或返回 `SKILL.md` 正文、秘密字段或 connector credentials。
- 前端状态只用于展示与排序；所有安装、授权、配置和导入动作仍由现有服务端权限检查决定。
- 用户无权读取某类别时，该类别不显示，不用前端隐藏替代服务端授权。

## 5. 对抗性验证设计

- 混合数据内有相同 ID 的专家、技能、连接器，确认 key 与动作按类型隔离。
- 已启用项目不匹配搜索词时不显示；匹配时必须排在所有未启用匹配项之前；类型筛选后仍维持该顺序。
- 技能包为空、共享只读包、重复 slug、无权限、部分目录 API 失败时页面仍保持可用，状态不误标。
- Unicode、大小写、空格及清空搜索均能正确筛选；无匹配项显示空状态。
- 大量技能包不会触发逐包并发请求；聚合 API 只返回当前用户可读 slug。
- 卡片与浏览器网络响应中不出现 connector 凭据或技能正文。

## 6. 验收标准

- `/connectors` 单页可浏览专家、技能和连接器；默认展示全部，顶部搜索一次查询三类资源。
- 用户可选类别筛选；启用/导入资源始终在符合搜索及筛选的结果中排在前面。
- 卡片状态分别正确标记专家已安装、技能已导入、连接器已启用。
- 原连接器配置/编辑/禁用、自定义 MCP 管理、专家创建、技能预览与导入仍可完成。
- 任意单类加载失败不阻断其他类；未经授权类别不暴露数据。
- 插件现有管理路由保持可达，不混入本次列表。

## 7. 影响范围与验证

- 前端主变更：`dashboard/src/pages/Agent/Connectors/index.tsx` 及其样式、必要的 API 类型/封装；专家和技能目录的读取沿用现有 API。
- 后端仅为技能已导入状态提供一个授权的聚合只读端点，并补充其 API 测试。
- 验证：新增/更新页面筛选、排序、部分失败、动作回归测试；`cd dashboard && npx tsc -b`；相关前端测试；若新增 API，再运行对应后端单测。完整 ship bar 仍按仓库要求执行 `make all`。

## 8. 已知限制

- “专家已安装”按当前用户拥有的 Agent 判断，不代表该专家当前正在运行。
- “技能已导入”表示至少存在于一个用户可访问技能包中，不代表该技能已挂载到某个 Agent 或已通过安全审查。
- 若目录本身加载失败，该类资源暂不可搜索；页面显示类别级错误并允许重试。
