# 入院申请单手动朗读设计

## 目标

患者在“确认您的入院申请单”阶段可主动朗读申请信息。页面进入该阶段时不自动播放；仅点击朗读按钮后才调用现有 Octop 语音输出。

## 方案

1. **改造现有按钮（采用）**：把“查看申请单详情”按钮改为“朗读申请单”，点击后按当前语言朗读申请单中的编号、患者、科室、医生、日期、住院类型、病区、诊断、来源、医保类型和确认状态。复用 `speakAssistant` / 已配置语音服务，避免增加重复操作。
2. 新增一个独立朗读按钮并保留原按钮。功能相同，但会在申请单区域产生两个用途接近的语音/详情按钮。

选用方案 1，因为现有按钮已经触发语音，只是当前播放的是通用核对提示。改造其文案与播放内容即可提供清晰的按需朗读，无需新增服务或按钮。

## 交互与数据流

- 在入院申请单确认阶段显示“朗读申请单”按钮。
- 进入阶段、查询完成、切换标签或刷新页面都不触发申请单朗读。
- 用户点击按钮后，前端从当前演示申请单数据构造本地化朗读文本，调用现有 `speakAssistant`；继续沿用语音输出服务的停止/播放行为。
- 不新增 API，不把申请单内容额外保存或发送给 AI。TTS 是否请求服务端由现有语音输出配置决定。

## 验收与失败场景

- 进入申请单阶段时 `voiceOutput.speak` 未调用。
- 点击按钮恰好调用一次语音输出，文本包含所有显示的申请信息且使用当前语言。
- 语音输出服务不可用时保留其现有失败处理，不阻止患者继续核对和办理。
- 键盘和读屏用户可访问按钮；中英文按钮文案一致更新。

## 验证

- 为进入阶段不自动朗读、点击后逐项朗读添加页面测试。
- 运行 Admission Demo 定向测试、TypeScript、ESLint、Prettier 和 Dashboard 生产构建。
