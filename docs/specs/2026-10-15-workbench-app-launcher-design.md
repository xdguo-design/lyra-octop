# 工作台多应用入口与项目上下文设计

## 目标

“内置平台”应作为应用入口展示多个可用应用，而不是固定打开星球乐园。新建任务时，所选项目/文件夹要成为新会话的账号级归属，并在输入区明确显示。

## 已确认范围

- 应用来源复用“创作”页：内置应用，以及账号登记的平台/服务条目。
- 可打开条目需要有链接。没有链接的待建设平台显示未部署状态，不尝试加载。
- Agent 卡片和“更多创作”快捷建议不出现在应用入口中；只列内置应用及账号登记的平台/服务记录。
- 同主机地址在平台内嵌入；外部地址使用带 `noopener,noreferrer` 的新窗口。
- 只在新建会话时使用当前项目/文件夹作为待写入归属；打开已有会话时展示服务端已有归属。
- 项目及文件夹名称显示在输入框工具栏，选择为空时不显示项目标签。

## 方案与选择

1. 在“内置平台”里另建静态应用清单。实现快，但与“创作”页的账号目录重复，容易不一致。
2. 复用“创作”页的内置应用和账号级平台/服务目录。目录只有一个来源；可打开 URL 的条目才启动。**采用此方案。**
3. 把“创作”页的 Agent 也放入入口。会混淆应用与对话对象，超出本次目标。

## 交互与数据流

打开“内置平台”后显示应用列表，选择内置应用或同主机服务时在内容区加载；选择外部服务时在新窗口打开。星球乐园继续使用现有地址配置及同主机 URL 校验。平台目录加载失败时保留内置应用并提示用户；条目 URL 无效时不创建 iframe。

侧栏选择项目或子文件夹后，空白会话的输入区显示“当前项目”及可选文件夹名。点“新建任务”时固定当前归属；发送第一条消息后创建会话并将归属写入现有 workbench API。切换项目/文件夹时，同步更新尚未发送的新会话目标。已有会话显示其实际归属，不因侧栏筛选而改变。

## 边界与失败处理

- 仅使用经现有同主机校验的 URL 创建 iframe；绝不向应用传递 LYRA 登录令牌。
- 外部链接通过新窗口打开并禁用 opener/referrer，避免外部页面控制工作台窗口。
- 账号数据读取失败时显示错误状态；内置应用仍可用。
- 新会话归属保存失败时显示现有项目保存错误，不静默清除错误。
- 空名称、取消输入不写入；项目/文件夹仍由现有服务端 API 校验所有权。

## 验收与验证

- 内置平台显示多个内置/已登记可打开条目，可切换同主机应用，并把外部服务链接打开到独立窗口。
- 无链接的待建设条目标记为未部署，不生成空 iframe。
- 选中项目或文件夹后，新建任务输入区显示正确上下文；切换目标后标签与最终新会话归属一致。
- 已有会话显示其真实归属；未归类会话不显示项目标签。
- 通过前端 TypeScript 构建；为 URL 决策与项目归属变更补充覆盖用例。
