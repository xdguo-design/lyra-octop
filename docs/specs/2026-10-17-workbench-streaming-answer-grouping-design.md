# 工作台流式回答合并设计

## 目标

工作台对一个用户问题只显示一条主 Agent 回答气泡。回复通过现有流式连接持续更新，分段内容以空行区分，避免把一次回答拆成多条小气泡。生成期间同时展示主 Agent 的可见工具/执行过程，让用户在最终答案完成前看到实际进展。

## 方案

只调整 `dashboard/src/pages/Home` 的展示层，复用聊天页已有的 assistant 消息分组和 `AssistantTurnView`。连续的同一主 Agent 文本合并为一个持续更新的回答；工具调用沿用聊天页的过程摘要展示，用户消息仍各自独立，非主 Agent 消息和私有推理内容继续过滤。

WebSocket/SSE 传输、消息存储、历史数据与后端接口均不变。正在流式生成的最后一段随外部 store 更新而重绘。

## 验收标准

- 同一个用户问题期间连续到达的主 Agent 文本显示在同一个回答气泡中。
- 后续流式文本追加后，回答气泡原位更新，不增加额外气泡。
- 工具或可见过程事件到达时，工作台在最终回答完成前即时展示过程摘要/进度；没有过程事件时保留“正在处理”状态。
- 新的用户消息会开始新的回答组；用户气泡和主 Agent 过滤行为保持不变。
- 合并后的 Markdown 保留段落、列表和代码块的可读性。

## 验证

为消息分组补充单元测试，覆盖相邻 assistant 消息合并、user 消息分界和不同 speaker 分界；运行相关 Vitest、`cd dashboard && npx tsc -b` 与 dashboard 构建。
