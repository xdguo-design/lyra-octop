# 聊天输入框 @ Agent 提及设计

## 目标

在聊天输入框输入 `@` 时，菜单展示当前聊天允许提及的 Agent，避免输入 `@` 后列表为空。

## 范围与约束

- 只列出运行中的 Agent；停止或启动失败的 Agent 不可选。
- 普通聊天沿用现有可选 Agent 范围：运行中的非团队 Agent；桥接会话只显示同一连接上的桥接 Agent。
- 团队聊天只列团队成员。
- 保留当前 Agent 不出现在提及菜单中的现有行为。
- 复用已有数据和 `buildMentionItems`，不新增接口或设置项。

## 方案

1. **推荐：修正 @ 菜单现有输入数据/展示逻辑。** 复用聊天页已有的可选 Agent 集合，定位列表为空的原因，并让输入 `@` 时显示符合上述范围的项目。改动集中在聊天输入和菜单，不扩大服务端能力。
2. 新建 Agent 查询接口并在菜单内单独加载。会增加请求、加载和错误处理，也会重复已有的聊天页 Agent 数据，不采用。

## 数据流与边界

聊天页提供权限和运行状态过滤后的 Agent 列表；提及 hook 排除当前 Agent 并按查询词筛选。输入有效的 `@` 后立即打开菜单，即使 Agent 列表仍在加载；数据到达后由现有候选构建逻辑显示 Agent 名称和头像。选择后沿用现有提及 token 插入逻辑。团队、桥接会话继续受当前聊天可达范围限制。

## 失败场景与验证

- Agent 停止或启动失败：不应进入候选列表。
- 搜索词不匹配：显示现有空状态，不显示无关 Agent。
- 团队或桥接会话：不能暴露当前会话不可达的 Agent。
- 回归验证：覆盖候选加载前打开菜单、数据到达后显示全部可用 Agent、空查询构建及当前 Agent 排除；运行相关 Vitest，并执行 `cd dashboard && npx tsc -b`。
