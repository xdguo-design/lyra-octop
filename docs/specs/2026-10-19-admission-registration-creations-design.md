# 入院登记原型接入创作平台

**状态：** 用户已确认，进入实施  
**日期：** 2026-10-19

## 1. 问题拆解

### 目标

将 `demos/admission-registration/` 中的 Vue 2 入院登记原型作为内置作品加入「创作」。用户从卡片打开后，在创作平台现有的全屏 iframe 预览栏中体验原型，并能返回创作列表。

### 约束与假设

- `localhost:5173` 是当前 Vite 开发服务器，不是部署地址；正式入口不得依赖它或用户手动启动开发服务。
- 原型需要读取 Octop 登录 token，调用 `/api/voice`、`/api/admission-demo/extract`，并访问自己的 mock API。前端必须由 Octop 同源托管，保留当前浏览器认证行为。
- 所有身份、地区与提交仍是模拟数据，不接真实医院系统；状态仅保存在服务内存，服务重启后清空。
- 不改动现有 React `/admission-demo`。新 Vue 原型作为单独作品加入创作。
- 创作卡片无需管理员启动服务；作品随 Octop 安装、更新和 Dashboard 构建发布。

### 失败模式与防护

1. **卡片有入口但前端产物未打包或路径不匹配**：Vite 使用 `/admission-registration/` base 并输出到 Dashboard 静态目录；生产构建检查该入口及入口资源可访问。
2. **iframe 跨源导致 token 丢失或语音/AI不可用**：前端从 Octop 同源路径加载，mock API 使用 Octop 同源 API 路由；保留当前 Authorization 与续期 token 处理。
3. **未授权调用或用户间模拟状态串用**：所有 mock API 要求 Octop 登录态；每个身份核验结果和提交记录绑定当前 Octop `user_id`，查询/提交时同时校验身份令牌与用户归属；AI 继续只转发当前转写并使用当前用户 token。
4. **误用于真实入院或患者数据**：页面与卡片保持“演示/模拟”说明；不增加持久化、HIS 连接或真实登记能力。

## 2. 方案对比与选型

| 方案 | 做法 | 优点 | 限制 |
|---|---|---|---|
| A（采用） | Vue 静态产物随 Dashboard 同源发布；mock API 以 Octop API 路由发布；创作卡片用现有 iframe 预览栏打开 | 不需要开发服务器或额外端口；可读取 Octop 登录态；复用创作的返回栏和关闭行为 | 需将 Demo 后端适配为 Octop 内的 API/domain 模块，并把静态构建纳入平台构建 |
| B | 注册独立本地服务并通过现有项目管理器启动，预览独立 loopback URL | 复用本地项目生命周期管理 | 独立 origin 无法读取 Octop localStorage token；为语音/AI增加 token 委派会扩大安全和实现范围 |
| C | 卡片直接打开 `localhost:5173` | 改动最少 | 依赖临时开发服务；正式运行、其他机器和跨源认证不可用 |

采用 A：原型已经依赖同源 token，直接将静态页面和 API 作为 Octop 内置能力发布，减少服务生命周期和凭证桥接复杂度。

## 3. 交互与数据流

1. 「创作」显示“智能入院登记”内置卡片，类别为小程序/应用。复用现有卡片标题、描述、编辑、收藏和操作栏能力；卡片使用 Vue 原型首页截图作为 16:9 封面，不复用旧 React Demo 的封面。
2. 点击卡片在当前创作页打开现有预览 overlay，标题显示作品名，顶部返回/关闭回到创作列表；不发生页面外跳转。
3. 前端从 Octop 静态目录 `/admission-registration/` 加载，Vite 构建 base 与发布路径一致。产物进入 Dashboard 打包与 wheel 发布流程。
4. API 路径保持 `/api/admission-registration/v1/*`。将现有 demo 后端路由与规则整理为 Octop 可导入模块；FastAPI adapter 负责路由与认证，`infra/` 负责校验、地区树、内存模拟身份/提交和 AI 候选校验。认证用户的 `user_id` 传入内存领域服务，身份与幂等提交记录按用户隔离。复用现有共享 JSON 字段合同，作为包资源供后端读取；前端仍在 Demo 源目录读取同一份合同。
5. 所有 mock API 都要求当前 Octop 用户认证。AI 路由将当前 Authorization 传给固定的 `/api/admission-demo/extract`，仅发送当前转写，不存储历史。平台 TTS/STT 继续使用 `/api/voice` 等既有路由。
6. 页面继续清楚标注医院/身份核验/地区和提交为 mock；数据不写数据库、不发给真实医院。

## 4. 对抗性验证设计

- 未登录请求每个 mock 路由均返回未授权；已登录调用流程正常。
- 非法字段、额外字段、非法地区父子路径、身份令牌伪造、跨用户重放身份令牌、重复提交不同内容均按现有 Demo 合同拒绝。
- AI 请求缺 token、越过文本长度限制、模型接口超时/失败时，不泄漏异常细节、不提交登记，并保留用户转写。
- 构建产物未生成、基础路径错误或静态入口缺失时，Dashboard 发布检查失败，不静默回退到 React 页面。
- 通过创作页组件测试验证卡片出现、预览 iframe 指向同源路径、返回和关闭 overlay 恢复列表。
- 通过 API 集成测试验证 mock API 认证、合同校验和内存状态；Dashboard TypeScript/测试/构建及后端目标测试通过。

## 5. 范围与不做事项

- 触及创作内置列表与中英文文案、Vue Demo 的生产构建配置、Dashboard 静态资源打包、Octop API/domain 接口和相应测试。
- 不新增数据库表、后台服务进程、端口配置、外链 URL、HIS/医院真服务或真实患者数据处理。
- 不改现有 React `/admission-demo`，不移除 Vue 原型的独立启动方式。

## 6. 已知限制

- 模拟身份与登记状态存在进程内存中，服务重启即重置。
- 原型仍是演示应用，不作为生产医疗登记系统。
- 页面作为受信任的 Octop 内置同源资源发布；不适用于在同一 iframe 中打开任意用户网页。
