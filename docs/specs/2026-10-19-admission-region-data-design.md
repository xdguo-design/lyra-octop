# 入院登记 Demo 全国地区数据设计

## 目标

用完整、离线、可校验的省/市/区县数据替换目前仅含少量示例地区的树，修复语音地区无法转成级联选择器代码的问题。详细地址仍由用户输入或语音候选填写，不试图提供街道、道路和门牌库。

## 现状与约束

- 前端和后端共享 `demos/admission-registration/contracts/regions.mock.json`，前端据此构建级联选项，后端据此校验地区代码路径。当前字段合同只允许空值或三个代码。
- 当前数据漏掉辽宁省沈阳市沈河区。未知籍贯会被丢弃，未知现住地区会降级到详细地址。
- 用户确认范围为中国大陆省市区县 + 香港、澳门区县，不包括台湾县市级数据。
- 上游 `uiwjs/province-city-china` 提供省/地/县层级 `level.json`，README 标注数据通过中国国家地名信息库接口更新、MIT 许可。当前上游树对直辖市和港澳采用省级节点直接包含末级地区的形式。

## 可选方案

1. **静态 JSON 合同（推荐）**：基于上游层级数据生成现有 `code/label/children` 树，运行时离线加载。地区路径允许 2 或 3 个代码：末级是省直辖区县时为省+区县，常规省市区县为 3 段。这样不伪造城市节点或行政代码；需同步调整前端递归选项和后端合同校验。
2. **Markdown 知识库**：保留地区名称、口语别称和地名解释供模型检索。适合补充 ASR 常见误听和历史别名，但不能可靠返回唯一行政区代码或验证父子层级，也无法直接填充级联控件；不作为地区主数据。
3. **JSON 主数据 + 可选别名 Markdown**：先接入方案1；如后续发现语音经常把地区名识别成别字，再单独增加别名映射/知识条目。当前没有证据需要增加这层，暂不实施。

## 推荐实施范围

- 将上游省/地/县数据转换为当前共享 JSON 格式，移除上游台湾空节点，保留大陆31个省级单位和港澳区县。
- 不插入虚构行政代码；支持真实数据树中 2 或 3 段有效路径，前端按树递归构建级联选项，后端与 schema 校验实际父子路径。
- 保持详细地址为自由文本；不导入街道、社区或门牌数据。
- 为未知现住地区保留原文候选到详细地址的现有安全回退；未知籍贯仍不自动猜代码，但在表单提供可见候选/人工处理，避免悄悄丢弃原话。具体交互在实施时按现有候选机制最小化处理。
- 增加结构测试（层级完整、代码唯一、路径可验证）和沈河区回归测试，覆盖截图原句中电话、籍贯、现住地区的分离回填。
- 固定上游快照的 commit 和 SHA-256，在 `demos/admission-registration/docs/` 记录来源链接、MIT 许可文本位置、数据日期和生成方式；不在运行时请求外部 API。

## 失败场景与防护

- 直辖市/港澳没有显式地级节点：保留真实的省→末级地区路径，并用 2 段合法路径表达，不虚构代码；测试验证这些地区可选择并可被后端接受。
- 数据代码重复、空子树或父子错误：加载/测试时校验唯一代码、节点层数和有效路径，不让错误数据静默进入表单。
- 上游数据过期或格式改变：固定导入快照并记录日期与来源；升级只通过明确替换和测试，不在用户运行时自动下载。
- 台湾数据在候选源中只有省级空节点，因此按已确认范围不导入；若未来需台湾县市级数据，需另外找可授权且可靠的来源。
