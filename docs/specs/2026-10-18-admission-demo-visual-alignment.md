# 住院登记 Demo 原型视觉对齐设计

## 目标

让 Octop 内的 `/admission-demo` 在桌面与自助机演示窗口中复现原型规定的组件位置、尺寸和比例，同时保留现有登记流程、语音能力、虚构数据提示与返回 Octop 入口。

## 现状与基准

原型文件 `C:\Users\xdguo\Downloads\PD_AI%E8%87%AA%E5%8A%A9%E5%85%A5%E9%99%A2%E7%99%BB%E8%AE%B0_%E5%8E%9F%E5%9E%8B%E5%9B%BE_AI%E9%97%AE%E7%AD%94%E4%BA%A4%E4%BA%92Demo_PRD_v1.2.html` 定义了 1536×1024 的自助机画布，并按画布比例适配显示。实施时以原型画布坐标为准，至少逐项对齐这些外框：顶部栏 x=12、y=0、宽 1512、高 98；左侧栏 x=31、y=99、宽 268、高 909；中心欢迎主视觉 x=303、y=99、宽 852、高 261；主交互区 x=317、y=361、宽 834、高 479；右侧区 x=1161、y=124、宽 347、高 726；底部语音区 x=316、y=851、宽 1201、高 157。顶部院标 x=43、y=12，导航 x=340、y=14、宽 696、高 74；主区标题行高 65；右侧患者卡高 472；语音胶囊宽 555、高 102。实现前逐一提取原型里可见按钮、标题、输入框、卡片及语音控件的坐标、尺寸、字体和间距，并将业务控件映射到对应位置，避免只对齐大容器。

当前页面以文档流和响应式 CSS 重排布局。761–1120px 时变成两栏，右侧卡片移到主卡片下方；桌面端也使用另一套顶部、留白、卡片和两栏对话布局。因此仅微调间距或字体无法满足原型对齐。

## 方案对比与选择

1. **继续修补响应式网页布局**：改动较小，但各断点仍会改变列数和组件相对位置，无法维持原型的一比一构图。
2. **采用原型固定画布并等比缩放（推荐）**：把 1536×1024 作为唯一布局坐标系，按可用视口统一缩放；三栏与底部语音区位置在各种窗口宽度保持一致。该方式直接复用原型的布局约束，最符合“位置和大小完全按原型”的验收目标。

## 组件与行为

- 将页面组织为原型的自助机顶栏、左侧流程导航、中间当前步骤、右侧患者/登记信息、底部语音操作区。
- 将现有身份核验、申请确认、资料补充、号码确认、费用确认、提交与成功状态放入对应区域；不更改状态机、字段校验、接口或模拟提交语义。
- 延续 Octop 语音输入/播放接口和离页停止播放行为。
- 在原型顶部工具区域保留“返回 Octop 平台”与“仅使用虚构数据”的提示；不显示真实患者信息，直到身份核验步骤完成。
- 仅调整 `dashboard/src/pages/AdmissionDemo/index.tsx` 与 `index.css` 中页面布局和呈现所需的内容，不触碰其他业务模块。

## 验收与验证

- 在 1536×1024 设计视口下，容器及可见交互组件的位置、尺寸、排列和原型坐标一致；完成逐组件截图比对。
- 在较窄窗口下整个画布等比缩小，不切换成两栏或把右侧区块挪到底部；不会出现横向变形或元素相互覆盖。
- 所有登记阶段和语音操作仍可用；资料确认门槛、仅虚构数据提示和身份核验前隐藏患者信息继续成立。
- 用本地浏览器检查设计视口及较窄窗口截图，并运行 AdmissionDemo 现有定向前端测试及 TypeScript 构建。

## 失败场景与防护

- **小窗口导致画布内容难以辨认**：保持画布等比，不局部压缩；让用户扩大窗口/全屏后查看，避免重新排版造成原型漂移。
- **较长对话或表单撑破固定区域**：只在原型对应的内容区内部滚动，固定步骤导航、患者信息、语音操作和主按钮位置。
- **绝对定位样式影响 Octop 其他页面**：所有新布局规则限定在 AdmissionDemo 页面根节点和自助机画布下，不使用全局标签选择器覆盖平台组件。
- **布局改动弱化隐私提示或过早显示患者信息**：保留现有核验状态门控，并在页面截图验收中检查身份核验前后的显示。
