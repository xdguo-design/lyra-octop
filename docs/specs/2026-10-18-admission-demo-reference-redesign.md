# 住院登记 Demo 参考图首屏改造设计

## 目标

将用户提供的医院自助终端截图作为首屏视觉目标：保留 Octop 内已运行的住院登记 Demo 和现有业务流程，将首屏改为五步式医院自助终端，包含护士欢迎区、四种识别方式、扫码进度卡、患者信息占位卡和语音入口。

## 约束与假设

- 现有固定画布 1536×1024 与等比缩放继续使用；不改平台路由、API、模型调用或认证。
- 仅重做首屏的视觉层次和识别入口，后续申请确认、AI 资料采集、短信确认、费用及模拟提交流程保持原行为。
- 身份证、医保卡、二维码、人脸均为交互演示，不连接硬件、微信、医保或人脸识别服务；界面必须显示演示提示，不宣称真实核验成功。
- 当前身份验证后显示虚构患者资料的规则保持不变；资料仍只在现有模拟核验操作之后出现。
- 参考图不作为整屏背景使用，避免图片内文字不可访问、无法本地化或与真实交互状态冲突。

## 方案比较

1. **推荐：只重做首屏内容和共享终端外壳。** 保留现有页面状态与 API；重建身份入口、右侧扫码/患者卡和底部语音区域，视觉更接近参考图，回归面较小。
2. **整页重写并更换全部业务状态。** 可以逐像素复制单张截图，但会丢失现有可运行登记流程，超出本次目标。

选择方案 1，因为验收目标是参考图视觉，登记 MVP 与已完成语音交互仍须工作。

## 布局与交互

- 画布保留 1536×1024；顶栏继续为医院品牌与分类导航。
- 以用户参考图比例（约 1.51:1）映射到当前画布，关键外框坐标保持：顶栏 `(12,0,1512,98)`；左流程栏 `(31,99,268,909)`；欢迎区 `(303,99,852,261)`；中心识别卡 `(317,361,834,479)`；右侧栏 `(1161,124,347,726)`，其中扫码卡高 234、患者卡高 472；底栏 `(316,851,1201,157)`。允许为 welcome art 和气泡留出内部叠放空间，容器边界不偏离超过 8 px。
- 中心识别卡内部标题行约高 65 px，识别卡横排四等分并保留 10–14 px 间隔；底部读卡演示区约高 148 px，左图示区域约占 2/3，右提示区约占 1/3。
- 欢迎区护士插画占左侧约 275×250 px，欢迎气泡位于其右侧并保持约 460×140 px；左流程栏底部用医院楼宇插画/图形作为装饰，内容不遮挡步骤或安全提示。
- 左侧步骤改为五个业务阶段：身份识别、确认入院安排、补充必要信息、费用与医保登记、完成登记。映射现有状态：`identity`→0，`application`→1，`details/supplements/phone`→2，`fees/final`→3，`submitted`→4。
- 顶部主视觉改为浅色医院走廊背景、护士插画与可访问的欢迎气泡；插画无文字、无标识，不承载操作。
- 身份识别主卡包含身份证、医保卡、扫码识别、人脸识别四张卡，默认选择身份证；选择后更新读卡区提示。点击“模拟识别并继续”复用现有 `verifyIdentity()`，不改变服务端逻辑。
- 读卡区明确显示“演示模拟识别，不会读取实体证件”；温馨提示标明真实业务需院内设备和权限。
- 右上扫码卡显示装饰用不可扫描 QR 图样和“扫码关注/办理进度”信息；“不扫码也可办理”切换到原手机号+验证码表单。手机号和验证码校验及错误提示原样保留。
- 右侧患者卡在身份确认前显示占位头像和提示，确认后才显示现有虚构患者信息。
- 底栏改为返回首页、语音主入口和人工帮助按钮。主入口按阶段工作：`details` 阶段启动原录音切换函数；其他阶段朗读当前步骤的简短指引（TTS），避免展示一个无效的首屏麦克风。保留 AI 回复重播入口。人工帮助按钮给出演示环境不可连接工作人员的明确提示，不伪装成真实呼叫。
- 四张识别卡使用原生 `button`，通过 `aria-pressed` 暴露选择状态；卡片组有可访问名称并能用 Tab/Enter/Space 操作。
- 中英文 locale 都新增相同键；图标继续用 lucide-react/现有 Ant Design，不添加依赖。

## 失败场景与防护

1. 用户把外观模拟误认为实际身份证/医保/人脸核验：四种方式都明确显示为演示；只有原模拟流程会进入虚构申请确认页。
2. 无法扫描装饰二维码：使用 `aria-hidden` 图案并明确标为演示二维码；真正可用的备用入口始终是可点击的短信表单。
3. 语音录音在不支持的阶段误启动：语音入口只在资料阶段启用；按钮提供可读名称和禁用状态，仍调用现有语音 hook。

## 验收

- 1110×764、1536×1024 两个视口都保持整屏比例缩放；按以上 1536×1024 区域坐标对照截图，主要容器差异不超过 8 px；首屏五步、四卡、欢迎区、右侧信息栏和底部语音入口可辨认且不互相覆盖。
- 四种识别卡片选择状态可切换；模拟核验后进入申请确认；短信入口对正确/错误验证码仍按原规则工作。
- 原登记全流程、语音转写/回复朗读和显式提交同意行为不回归。
- 运行 `npx vitest run src/pages/AdmissionDemo`、`npx eslint src/pages/AdmissionDemo/index.tsx`、`npx tsc -b`、`npm run build`。
