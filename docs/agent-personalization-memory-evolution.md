# Agent 个性化、记忆与进化、外部执行器方案

状态：**设计与分期实施建议**（不是已上线功能说明）
适用范围：lyra-octop 主控工作台、专家 Agent、ACP 执行器。

## 产品定位

用户只和主 Agent（小恐龙）交互。主 Agent 持有长期用户关系、任务规划和权限审批，按需将任务委派给内部专家或 Kilo Code 等外部编程执行器。**外部执行器不直接写主 Agent 的人格或长期记忆**。

## A. 角色档案 Persona Profile

已有基础：agents.persona_mbti、system_prompt、SOUL.md 与 MBTI 页面（见 docs/personas.md）。

新建一个可独立版本化的角色配置模型（建议 agent_persona_profiles）：`agent_id`、`revision`、`display_name`、`avatar_asset_id`、`visual_theme`、`role`、`backstory`、`speech_style`、`values`、`boundaries`、`proactivity`、`mbti_code`、`custom_instructions`、`created_by`、`updated_at`。

- 必须区分“角色表达”与“系统权限”，人格不能覆盖安全或工具策略。
- 头像、性格、能力、模型、记忆分别编辑；切换头像不改变任务/身份。
- 用户预览：展示三条真实场景对话（闲聊/委派/任务失败），确认才发布。
- 主 Agent 与执行 Agent 共享必要任务上下文，但不共享私密人格资料默认全集。
- 兼容：旧的 MBTI/system_prompt 读取为默认档案；不要直接覆盖已有 SOUL.md。

## B. 分层记忆与治理

已有基础：MemoryPanel、Atom/Episode/Journal/候选审核、自动提取设置、memory.sqlite 在线维护；不得将“已有记忆管理”误说成“完整自我进化”。

| 类型 | 作用 | 推荐治理 |
| --- | --- | --- |
| Working | 当前会话/任务上下文 | 按任务结束过期 |
| Episodic | 已完成任务、反馈与结果 | 来源、时间、任务 ID |
| Semantic | 长期事实、稳定偏好 | 置信度、冲突解决、用户纠正 |
| Project | 代码/文档/决策 | 严格的项目/租户隔离 |
| Procedural | 经验证可复用的步骤/Skill | 仅测试通过后发布 |

所有记忆条目应包含 `owner`、`scope`、`source_event_id`、`confidence`、`sensitivity`、`observed_at`、`expires_at`、`supersedes_id`、`status`。UI 必须能搜索、查看来源、修改、忘记、导出、关闭个别捕获类别。不可把推断/一次性任务内容直接升级为永久事实。

**检索门禁**：工作任务只加载与用户、项目、Agent 权限匹配的记忆；向外部 Agent 仅传最小可用摘要，绝不下发凭证、原始隐私记录或未经允许的跨项目记忆。

## C. 可控进化（不是模型自我训练）

任务 -> 自动评估和用户反馈 -> 提取经验候选 -> 隔离运行回归用例 -> 人工审批 -> 发布新策略/Skill/角色版本 -> 观察与回滚。

- 进化目标以任务成功率、重复错误率、人工接管次数、成本、时延衡量；建立变更前后的基线。
- 自动归纳反馈可以，自动扩权、自动更换权限策略、自动启用网络/命令执行不可以。
- 新策略要有版本、依据、审核人、回滚目标和可观察记录。
- 失败经验与成功经验都记录，但保留“任务实例”和“泛化规则”的区别。

## D. Kilo 等外部执行 Agent

优先复用现有 ACP outbound，按 adapter/runner 管理；使用者可以配置 Kilo、Codex、OpenCode，也可增加其他 ACP 服务。

- 预置 Kilo runner：`kilo_code`, command=`kilo`, args=`["acp"]`，默认关闭、不可信。
- 主 Agent 负责委派和汇总；Kilo 负责限定目录里的编程与测试，不直接持有平台总权限。
- 任务契约：`task_id`、`parent_task_id`、`runner_id`、`workspace`、`allowlist`、`deadline`、`budget`、`status`、`artifacts`、`audit_trail`。
- 要求进度、失败原因、权限申请、可复现命令、diff/测试证据、审查门禁；禁止把“命令成功退出”当作“业务验收通过”。
- 对外只传最小上下文，避免不同项目之间的泄露；每个任务使用隔离工作区，写入须审批。
- 生产环境不默认启用 `--auto`，不可把外部 Agent 直接挂载宿主机敏感目录。
- v1 使用 stdio ACP；如将来引入远程 Kilo 服务，需要独立认证、网络策略和协议适配层。

## E. 工作台设计与实施顺序

### P0：可发现与可用

- 主 Agent 的「角色档案」入口放在角色卡/抽屉，不再在左侧层层展开。
- Agent 卡支持角色头像、性格标签和一键预览；全站统一小恐龙主形象。
- 当前已有 MBTI、记忆和 ACP 功能必须可在主工作台到达；不再藏在独立管理子系统里。
- 把新增的 Kilo ACP runner 展示在执行器列表中，做只读烟雾测试。

### P1：记忆治理闭环

- 记忆搜索/纠正/删除/来源查看及项目空间隔离。
- “这次应该记住什么？”候选审阅，用户可拒绝。
- 离线 E2E：同项目多轮任务继承上下文、跨项目不泄露、纠正覆盖旧事实。

### P2：可控进化闭环

- 任务完成后评估、经验候选、离线回归、审批、发布与回滚。
- 评估面板：过去 7/30 天的错误类型、反馈、成功率及变化证据。
- 真实 Kilo 编程任务在隔离工作区进行 PR、测试、审查和报告。

## 验收门槛

1. 可在一个页面修改主 Agent 的人格并预览，不会修改执行权限或清空历史。
2. 用户偏好跨会话有效；显式删除后不再检索；跨用户/项目隔离通过。
3. Kilo/其他 runner 在允许的工作区完成读代码、修复测试；权限请求可见且可拒绝。
4. 进化只生成经过回归和人工批准的新版本，可一键回滚。
5. 任何自动记忆/进化操作都有可审计事件；不把自生成结论直接写作事实。

## 当前本次改动边界

本次仅增补 Kilo Code 内置 ACP runner、相关 UI 文案、静态单元测试断言及此方案文档。**没有**安装/登录 Kilo、执行端到端 ACP 会话，也**没有**完成新的人物档案 API 或记忆进化引擎。
