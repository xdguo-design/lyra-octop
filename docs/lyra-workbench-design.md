# LYRA 私有云工作台设计与验收（2026-10-14）

开发分支：`dev`。页面入口：`/home`。技术栈：React / TypeScript / Octop 的原生 Agent Team + WebSocket Chat。

## 一、交互结构

参考 Manus 的**信息架构**，不照搬视觉素材：

- 左侧：品牌、新对话、工作台/团队/知识库/自动化/插件/模型管理、最近会话、私有部署状态。
- 中部：工作台主区域为“主 Agent 对话”，默认显示欢迎入口，开始会话后仅显示主对话正文；输入栏固定在底部。
- 右侧：主 Agent 状态、真实 Agent Team 成员可用性、已安装内置平台入口；这里不是第二个聊天窗口。
- 一旦发出消息：欢迎卡片切换为同一工作台内的聊天历史；用户不被强制导航至 `/chat`。
- 会话区只投影用户和主 Agent 的正文。团队成员发言、执行工具轨迹和系统信息不会混入对话气泡。
- HITL 人工审批仍须进入原生“高级对话”完成，不能在简版首页中悄悄跳过授权。

## 二、主 Agent / 多 Agent

`selectPrimaryAgent` 选择顺序：

1. 已启动且有成员的 Team；
2. 已启动的空 Team（展示配置不完整）；
3. 名称明确表达主控/调度的已启动专家；
4. 普通运行中 Agent（仅单 Agent 对话，明确展示非团队状态）。

主控可通过右侧选择器在当前已启动的 Team 之间切换，选择记录仅保存在当前浏览器；存在可用 Team 时，不允许误把普通 worker 选成主控。**不会自动替用户创建或启动 Team，不会虚构执行状态。** 真正的多 Agent 任务分发走 Octop 原生 Team host，主页只对 Team host 发送信息。具体成员管理在 `/experts`。如果用户未配置 Team，页面不宣称“自动分发已就绪”。

聊天链路复用 `octopThreadsApi.create/list/history` 与现有 `useChat` / WebSocket Store（包含流式回复、断线续传等）。本次改动没有重复构造一个假的聊天 API。

“只保留聊天内容”目前仅约束工作台**展示层**：底层会话、附件、调度日志和审批信息仍由原有系统存储，方便审计和高级对话查看。若要后端物理删除工具轨迹，属于单独的数据保留策略，不应在展示层实现。

## 三、星球乐园是现有内置工作台（不是 Agent）

点击「内置平台 / 星球乐园」时，进入覆盖整个工作台的独立平台视图：常驻顶部仅有返回、平台名、地址设置、浏览器全屏、独立窗口打开与退出；平台 iframe 占其余全部空间，不再用居中浮窗。**不重建星球乐园的首页、不凭空添加它的业务功能和项目卡片。展示内容来自已开发星球乐园自身的服务。**

地址配置：`VITE_LYRA_PLANET_URL`，或在平台顶部设置；本地保存当前浏览器的 `octop:workbench:planet-url`。缺省从当前浏览器主机名与端口 `8130` 组合，以修复原来固定 `127.0.0.1` 导致从其他机器访问 NAS 时指向访问者电脑的问题。

安全边界：

- 嵌入地址必须为 HTTP(S)，不能含 URL 用户名密码，hostname 必须与工作台一致。支持同主机不同端口。
- 不向 iframe 传递 Octop JWT、Key 或授权头。平台继续调用自身的 Agent/LLM 后端；不能仅凭嵌入宣称已打通 Octop 的 Agent/LLM。
- 如果工作台使用 HTTPS，URL 校验直接拒绝 HTTP 平台地址，以免浏览器阻止混合内容。
- 平台独立打开入口为受验证的同主机 URL，可用于平台禁用嵌入、需要跳转登录或不支持 iframe 的情况。
- 平台服务需允许通过 iframe 嵌入（CSP `frame-ancestors` 和 `X-Frame-Options` 配置），并实现自身认证。
- 正式的跨平台 Octop Agent/LLM 能力复用需建立后端授权 API / 短期能力令牌和逐平台权限范围，**不可**直接用 `postMessage` 发送任意提示词请求、明文密钥或主会话 JWT。

## 四、验收点

1. `/home` 默认看到 Manus 式左侧导航、中间对话/输入、右侧 Agent Team 状态和内置平台入口三栏。窄屏隐藏辅助栏，保留中央聊天入口。
2. 启动过且配置成员的 Team 成为主 Agent；未配置团队时可聊天，但准确提示单 Agent 模式。
3. 工作台首次发送在当前页面创建线程，后续消息追加同一线程；左侧可打开过去的会话。
4. 工作台会话不显示 member agent 消息和工具轨迹，主 Agent 结果可显示。
5. 流式生成时可停止；需要 HITL 审批时必须显式告知，跳转原生高级对话。
6. 进入星球乐园后，占用除细顶部栏之外的完整浏览器工作区；关闭后恢复原工作台/会话。星球乐园必须呈现它自己的真实页面，而不是 LYRA 伪造的“平台 Agent”页面。
7. 工作台主机不是 localhost 时，平台默认地址跟随同一私有云主机；错误或不可信 URL 被拒绝。
8. 小屏幕导航不溢出，键盘可操作主要按钮；发送支持 Enter、换行支持 Shift+Enter。
9. 主业务代码验收需要在带有完整 `dashboard/node_modules` 的环境中执行：`cd dashboard && npm ci && npm run build && npm run test -- src/pages/Home/workbench-model.test.ts`，再做手工真实聊天和平台服务端到端测试。

## 五、当前未完成的系统能力

- 平台独立的 Agent/LLM 可以由平台**自己**调用；Octop 对这些平台统一发放可控的代理调用权限尚未实现。
- “会话只显示聊天文本”已支持；彻底不存储执行日志不是此次更改目标。
- 平台在线探测、自动发现、单点登录、统一 Agent 能力网关，需要后续联调平台服务并增加服务端适配器。
