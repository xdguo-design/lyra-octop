# 入院登记项目弹窗样式统一

## 目标

只在 `demos/admission-registration` 内统一各页面模态弹窗外观，按用户手机截图采用白色圆角面板、浅色边框、柔和阴影、统一遮罩和底部输入/操作区。其他项目和 Dashboard 不在范围内。

## 覆盖范围

- 共用 `ConversationDialog.vue`：首页、表单页和其他登记流程页面的手动输入入口统一使用首页聊天外观；首页意图分类、表单 AI 回填及身份核验前的提示逻辑保持各自原样。
- `App.vue` 中三个 Element UI 对话框：识别内容修改确认、退出办理、空闲超时提醒。
- `KeypadDialog.vue` 是表单输入旁的非模态数字键盘，不属于贴底遮罩模态布局：保留锚定位置和点外关闭行为，只统一白色面板、圆角、边框与阴影。
- 不修改 `dashboard/`、其他 Demo、后端或其它仓库范围外文件。

## 方案与取舍

在本项目的 `frontend/src/style.css` 里为 Element UI 的 `.el-dialog__wrapper`、`.el-dialog`、标题、内容、footer 和遮罩增加一致的项目级规则；为数字键盘补同款面板表面样式。`ConversationDialog.vue` 已有对应外观，继续作为参照。

保留每个弹窗的标题、正文、按钮文案/顺序、关闭开关、遮罩点击/ESC 行为和表单逻辑。桌面端仍按各自内容宽度居中；手机端让 wrapper 贴底，dialog 全宽且高度受动态视口限制，正文区单独滚动，footer 不随正文滚出可视区并避让安全区。数字键盘仅共用面板表面，不改定位与交互。这样统一外观而不把确认对话框改成聊天内容，也不破坏数字键盘的就近操作。

备选方案是把数字键盘也改成模态底部面板；这会遮挡其正在编辑的电话字段并改变交互，因此不选。

## 失败场景与防护

- 长文本或语音确认内容超过屏幕：只让正文区域滚动，按钮区留在面板内。
- 小屏上固定宽度和footer挤出视口：手机断点覆盖 Element UI 行内宽度，wrapper 使用贴底 flex 布局，dialog 限高，body 内部滚动，footer 固定在面板底部并保留安全区间距。
- 特殊确认流程意外变得可关闭：仅改 CSS，不改 `close-on-click-modal`、`close-on-press-escape`、`show-close` 或现有事件。
- 数字键盘被误改成遮罩弹窗：只给 `.keypad-panel` 设置表面样式，不改变定位、z-index 或点外关闭逻辑。

## 验收

- 在首页、身份核验、申请单、表单、核对页分别打开“手动输入”，确认均使用同一聊天弹窗样式；首页意图分类和表单 AI 回填仍只在对应阶段触发。
- 逐一触发三个 Element UI 对话框：AI 候选值与当前字段冲突时打开修改确认；底栏“退出登录”打开退出确认；空闲计时进入提醒阶段时打开超时提醒。确认桌面面板表面统一；手机上都贴底、全宽、顶边圆角，正文可滚动，底部按钮可见。
- 数字键盘仍靠电话输入框打开，点外关闭，且采用同款白色边框圆角阴影。
- 识别修改确认和空闲超时提醒仍保持原有不可关闭设定；退出确认的按钮和取消行为不变。
- 在 390×844 手机视口和桌面视口检查显示；手动输入聚焦并弹出软键盘时，输入区、正文滚动和操作区仍可用。执行项目现有前端格式检查和 Vite build。
