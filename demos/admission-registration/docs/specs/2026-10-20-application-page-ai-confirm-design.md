# AI 对话模式下确认本人入院申请单

## 目标

AI 对话模式进入“本人入院申请单”页后，页面内容继续显示并保留状态。AI 对话说明当前申请单信息，只有用户点击对话框中的“确定申请单并继续”才进入表单页。普通自助流程继续使用申请单页面上的操作。

## 实现方案

- 以 `conversationVisible` 标记 AI 对话模式；只在对话框打开时显示对话框专属确认按钮，并隐藏申请单卡片上的“确认并继续”，避免两套推进入口。收起对话后，页面恢复普通操作。
- 身份核验查询完成后，根据有效申请单构造助手消息，数据直接来自申请单 API：展示申请单号、由现有 `maskName()` 处理的患者名、科室、计划入院时间、医生、住院类型、诊断、病区和状态，不调用 LLM 改写事实。
- 唯一有效申请单保持现有自动选中逻辑。确认按钮复用 `continueWithApplication()`；请求期间禁用按钮，继续复用 generation、身份令牌及服务端有效性检查。
- 无有效申请单、多份有效申请单或查询错误时，助手说明对应状态，不显示确认按钮。AI 对话不会自动离开申请单页。用户仍可主动退出办理。
- 页面字段、申请单数据及各阶段现有对话数组均留在父级状态中；切页不主动清空。新身份核验/重置继续走现有清理流程。

## 失败场景与防护

- 查询返回零份或多份有效申请单：不显示推进按钮，说明联系现场工作人员；不猜测或自动选择。
- 用户连点确认：复用 `selectingApplication` 防重入，并在请求中禁用按钮。
- 确认请求期间身份/流程变化，或申请单失效：复用现有 generation、token 和服务端归属校验，迟到响应不推进页面。
- API 查询失败：停留在申请单页，显示明确错误；不伪造申请单详情或确认状态。

## 验证

- AI 模式显示申请单事实摘要和对话框确认按钮；普通模式仍显示页面确认操作。
- 点对话框按钮只发起一次申请单确认，成功后才进入表单；查询空/多条/失败时不能推进。
- 页面切换/回退不因组件卸载清空父级表单值、申请单数据或各阶段对话记录。
- 在 Demo frontend 目录运行：`npm test`、`npm run typecheck`、`npm run build`、`npm run build:dashboard`。
