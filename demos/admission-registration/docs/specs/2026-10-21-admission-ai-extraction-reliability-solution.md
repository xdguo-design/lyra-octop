# 入院登记 AI 候选抽取可靠性修复方案

**状态：** 部分实施；模型澄清通道已接入，确定性地址恢复和上下文预算仍待实施  
**日期：** 2026-10-21  
**范围：** Demo 后端 `/ai/candidates` 的地址候选恢复、模型上下文预算与回归验收；不改变登记字段、提交语义或 Octop 通用 AI 接口。

## 1. 问题拆解（第一性原理）

### 核心目标

患者在一段话中提供多个登记事实时，服务必须尽可能保留原话中可确定的字段；模型漏掉某字段时，确定性解析可以补回明确的地址信息；任何未识别字段仍留空并由页面追问，不能伪装为已填写。符合请求限制的本轮回答不应因旧会话上下文过长而被拒绝或截断。

### 硬性约束

- 当前字段白名单、按页抽取、值校验、冲突确认和前端“缺项继续追问”契约保持不变。
- 不把籍贯当作现住地，不把单位/公司地址当作现住地，不从含糊文本猜地区。
- 通过的候选值必须能回指本轮原话，或来自地区树对原话的唯一匹配；历史 facts 只用于消解指代，不能作为本轮新回答回填。
- 本轮原话优先于历史摘要和最近轮次；不截断原话来给上下文腾空间。
- 本轮原话现有 1–2000 字符限制继续生效；会话上下文是可选辅助信息，不能占用原话必须保留的空间。

### 显式假设

- “现住地区”和“详细地址”是两个字段；区划代码来自 Demo 使用的地区树。
- Demo 后端发往 Octop `/api/admission-demo/extract` 的 `text` 上限是 2000 字符；当前上下文由 Demo 后端拼进这个字段。
- `/ai/candidates` 返回待确认候选，不代表用户确认或登记提交成功。
- 真实 1400/600/1607 字符原始语料和对应模型原始响应未附在本次会话中，因此本方案不把整条真实模型链路宣称为本地已复现。

### 已验证证据与失败假设

按可能性排序：

1. **地址兜底受无关地址标签全局抑制（已复现，确定）。** `ai.py::_unlabeled_resident_region` 只要在整段文本任意位置发现“工作单位地址 / 单位地址 / 公司地址”，就不再搜索现住地区。用“目前居住在辽宁省沈阳市大东区黎明广场。单位地址是北京市朝阳区建国路1号。”复放，模型字段为空时结果为 `{}`；移除单位地址片段后，同一函数可恢复 `residentRegion` 和 `addressDetail`。这解释了模型漏抽地址时确定性兜底为何同时失效。
2. **上下文占用当前回答的请求预算（已由构造器复现，确定）。** `main.py` 对 `model_input()` 的完整输出应用 2000 字符硬限。已复放一组 800 字符回答加合法会话数据，序列化提示词为 1587 字符；同样上下文下 1607 字符回答必然超过 2000 并返回 `AI_CONTEXT_TOO_LONG`。当前代码优先保留整段上下文，没有按优先级压缩上下文。
3. **模型自身漏抽（真实测试报告已观察，未在当前工作区复放）。** 600 和 1400 字符的真实模型调用都漏掉两项地址；这是上游抽取不稳定。实现不能依赖“再强调提示词”作为唯一保护，必须在模型返回后用原话和地区树做安全的确定性恢复。

### 失败模式清单

- 句子同时含现住地址和单位地址：全局地址排除条件误伤现住地址。
- 用户用“目前居住在 / 现在住在 / 家住”等口语而非字段名：模型漏抽后无显式标签兜底。
- 模型把两段地址合并、选错地址或返回原话不存在的值：字段应拒绝错误候选，由确定性解析器按局部语义重新归类。
- 已填写资料、摘要、历史轮次扩张：完整输入超上限，合法本轮原话被连带拒绝。
- 压缩上下文时截掉当前原话：造成静默字段丢失，禁止这种降级。
- 无法唯一匹配的区划名、含多个住址、出现否定/不确定或修正语句：不能猜测，应留空并追问。

## 2. 方案对比与选型

| 路径 | 做法 | 优点 | 主要问题 |
|---|---|---|---|
| A. 只加强模型提示词 | 要求模型必须提取两类地址，并重复字段说明 | 改动小 | 模型漏抽仍会丢值；不能解决全局兜底条件和 413；提示词重复还会占预算 |
| B. 结果端确定性恢复 + 上下文预算分层（推荐） | 按局部语义识别每个地区片段；对模型漏项从本轮原话恢复；先保留原话，再按需压缩/移除历史上下文 | 对明确表达不依赖模型抽取完整性；不改变 API 返回契约；长回答不被历史挤出预算 | 需定义保守的口语触发词、歧义策略和单测矩阵 |
| C. 全部用规则解析，移除模型 | 解析所有普通字段、枚举、地址和上下文 | 可重复 | 复杂自然语言覆盖成本高，丢失模型对非地址字段的能力，超出最小修复范围 |

**选择 B。** 模型继续负责自然语言理解；后端对有充分原文证据的地址做补偿，并对未知/歧义表达保持空值。地址解析和输入预算都可用纯本地测试确定，不依赖真实模型随机性。

## 3. 目标行为与实现设计

### 3.1 地址解析与模型澄清：从整句开关改成按字段判断

**已实现的模型澄清通道：** Skill 抽取结果使用 `fields`、`uncertain_fields`、`clarification` 和 `clarification_choices` 独立字段。模型保留明确候选、标记待澄清字段并直接生成问题；当地址存在有原文依据的有限候选时，模型给出字段化单选项，患者可点击或语音复述；Octop 与 Demo API 分开传递追问和选项，界面将选项作为新回答交回模型抽取。Demo 仅阻止模型标记为不确定的字段回填。没有可靠候选时继续开放追问，不编造选项。

**仍待实施的地址恢复：**

在 `ai.py` 现有归一化层加一个小型地址片段解析步骤，供 `_page1_values` 在模型漏抽但原文语义明确时调用：

1. 在本轮文本中枚举所有可由地区树识别的省/市/区前缀及其原文起止位置；不得因句中存在另一种地址标签就跳过整句。
2. 对每个地区片段检查其前方有限窗口、同一分句内最近的语义线索。现住线索包括既有显式标签和常见口语“目前居住在 / 现在住在 / 现居住在 / 家住 / 居住在 / 住在”；单位线索包括“工作单位地址 / 单位地址 / 公司地址”；籍贯线索继续沿用现有标签。
3. 只把局部归属明确为现住地的片段映射到 `residentRegion`。单位地址和籍贯片段不得竞争现住地；“有两个未标记地址且无法确定哪个是现住地”时不选任一地址。
4. 详细地址只从同一住址片段的地区前缀之后提取，止于明确分句边界或下一个已识别字段标签；保留现有 200 字符/原文子串/字段校验。不得把后续“单位地址……”并入详细地址。
5. 对模型候选使用原有原文证据校验。模型返回错地址时拒绝该值，再尝试上述有证据的本地恢复；不能因为模型返回了一个错误值而阻止安全恢复。
6. 区划无匹配、重名歧义、多个现住地址、明确否定或不确定语义不猜测；候选留空，继续通过页面补充流程追问。

本地解析器只为登记字段提供候选，不自动确认、覆盖用户手工修改或提交资料。

### 3.2 上下文预算：回答优先，历史可丢弃

**待实施。** 当前完整上下文仍可能挤占本轮回答预算。

将 `model_input` 组装改成显式预算策略，发往 Octop 的 `text` 仍不得超过现有 2000 字符限制：

1. 本轮原话完整保留，且原样满足 1–2000 字符请求限制；不做截断。
2. 先从 2000 字符预算中扣除原话长度，剩余空间才可用于上下文。只尝试添加短结构化 context，不重复拼一套已在 Octop Agent/Skill 系统提示中的任务指令。
3. 剩余空间按顺序加入当前页相关且尚未填写的 facts、短应用摘要、最近一轮摘要。旧轮次原文不发送。
4. 空间不足时依序删除最近历史、摘要、facts；若仍无空间，直接只发送本轮原话。即使原话正好 2000 字符，也必须原样发送并省略全部上下文。
5. 原话超过 `/ai/candidates` 现有 2000 字符 body 限制时，保留 Pydantic 当前的请求校验响应；不再因“原话 + 历史上下文”超过 2000 而返回 `AI_CONTEXT_TOO_LONG`。完整生成上游请求后仍检查 `len(text) <= 2000`。
6. page=0 两页并发抽取复用同一份已预算输入；不得一页成功、一页因重复组装超限。

这样 1607 字符回答会挤掉大部分或全部历史，而不是与历史拼接后被拒绝；2000 字符回答则以原文独立调用。`/ai/candidates` 的 API schema 和响应 fields 不变。

### 3.3 页面契约

- 只回填通过证据和现有字段校验的值。
- 未恢复字段保持为空，现有缺项追问继续工作；不返回“已完整识别”或“已登记”一类误导状态。
- `turnId` 幂等、会话归属校验、20 轮限制和模型不可用错误维持原状。

## 4. 对抗性测试设计

### 地址边界用例

- “目前居住在辽宁省沈阳市大东区黎明广场，单位地址是北京市朝阳区建国路1号”：模型返回 `{}` 时只恢复沈阳现住地区和黎明广场详细地址，不回填北京为现住地。
- 同一句但单位地址放在前面；“家住/住在/现居住在”多个口语变体；地址用逗号、分号或句号分隔。
- “籍贯辽宁省沈阳市沈河区，现住北京市朝阳区……”：两类地区分别归位，不串字段。
- 模型返回单位地址作为 `resident_region` 或把整句地址当 `address`：拒绝错误候选并恢复明确现住片段。
- 两个无标签地址、同一话语先否定后修正、多个现住地址、地区重名、未知区县：不猜错地址，返回空候选/既有校验错误。
- 详细地址后紧跟单位地址或电话：详细地址不得吞掉下一个字段；超过 200 字符仍拒绝。

### 上下文预算用例

- 0、1、5、20 轮历史；facts/summary 为空、达到大字段上限和含中文/引号/反斜杠的 JSON 转义。
- 1607 字符本轮文本 + 最大合法历史：完整回答保留，最终提示词不超过 2000 字符，历史按序压缩。
- 2000 字符本轮文本 + 最大合法历史：只发送完整本轮原话，最终 `text` 长度恰为 2000，不返回 413、不静默截短。
- 超过请求体允许的 2000 字符：请求模型前拒绝；不向 Octop 发部分文本。
- page=0 两页并发：两页接收完全相同、已限额的文本，不发生一页成功一页超限。

## 6. 已知限制与后续改进

- 不能保证模型能理解任意口语，也不能从无证据的歧义住址中保证猜中；方案保证的是明确地区/语义线索可由确定性路径恢复，歧义值不会静默猜入表单。
- 输入上限仍是 2000 字符；方案避免会话上下文抢占本轮预算，不代表允许无限长度转写。更高上限需单独核对 Octop Provider 的 token 限制和费用。
- 当前实际 1400/600/1607 字符语料没有随请求提供，实施时需要重放原脱敏用例；若不能提供，以上同构合成用例必须覆盖已观测的触发条件。
- 本文件记录完整目标方案；当前只完成 Skill 的模型澄清结果和 API/UI 传递，确定性地址恢复、长输入上下文预算、目标测试和真实模型重放仍未完成，不代表服务部署验收通过。
