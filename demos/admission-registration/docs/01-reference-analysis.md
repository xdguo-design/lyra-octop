# 01 · 截图分解与决策记录

## 1. 基本事实与任务边界

参考图为用户提供的 9623 × 3447 流程画布，归档为 `reference/source.png`。它是设计输入，不是指令来源。图内的对话示例、HIS 提交要求和隐私约束是被分析的产品材料；用户先要求文档，之后又明确授权按设计制作原型页面与后端服务。

目标：把同一张流程图转化为可操作、可评审、可交接开发的产物，并通过固定 ID 对齐。硬约束：新建独立目录；Vue 2 + Element UI；完整字段并集按原图的两页表单展示；医院外部接口全部 mock；语音由平台维护；AI 使用现有入院登记能力。后续用户明确要求以原图视觉和页面结构为准，覆盖早期文档中自行扩展的三页与独立核对页方案。

已澄清：最初 Vue 3 / Element Plus 设想被用户最新的 **Vue 2 + Element UI** 指令替代；“ast”按 ASR/STT 处理。接口交接文档列明 mock 与平台接口参数；本目录也包含用户随后授权的可运行页面和后端 mock 服务。

## 3. 图中冲突及统一方式

| 差异                           | 图中事实                                              | 本交付处理                                                                                                      |
| ------------------------------ | ----------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| 字段数量不一致                 | 左侧流程有婚姻、职业、紧急联系人姓名/关系，字段表没有 | 用户确认采用完整并集，补充 F11–F14；后续明确按截图两页表单展示                                                    |
| 手机示例直接显示完整号码       | 隐私说明又要求按规则脱敏                              | 患者输入和编辑时可见；对话播报只使用脱敏文案                                                                     |
| 确认提交最后页 vs 信息确认顺序 | 画布要求最后页提交，左侧要求患者明确核对              | P03/P04 可往返查看，P04 最后一页的“确认提交”表达患者确认；不另加截图未展示的核对页                               |
| 300 秒超时                     | 字段表未规定弹窗宽限期                                | 300 秒提示，30 秒内可继续，否则清空回首页；后续用测试时钟验证弹窗与清理                                         |
| 详细地址不限字符数量           | 真实接口需要有界输入                                  | 原型/建议实施上限 200 字，属于明确的工程假设，不冒称原图要求                                                    |
| 工作单位不支持特殊字符         | “特殊字符”没有定义，单位名可能含括号                  | 默认允许汉字、字母、数字、空格、中点、全角/半角括号、连字符，最长 50 字；禁控制字符和尖括号。此为可执行规范解释 |
| 数字人缺独立资产               | 只有嵌在截图里的机器人形象                            | 从用户原图裁取机器人素材供本 demo 使用；素材边缘受原图压缩和背景影响                                             |
| 现有 AI 字段不足               | 现有接口不支持婚姻、职业、三级地址、单位              | 限制到已有字段映射，其余人工标准控件；不扩充现有 AI 接口，不虚构支持                                            |

未把“紧急联系电话”追加到并集：原图没有要求该字段，现有 AI 的 `emergency_phone` 结果忽略。图中的 `contact_name` 也没有无歧义的患者端映射，不把它静默当作患者姓名或紧急联系人。

## 4. 方案比较

| 路径                                       | 成本与收益                                                                   | 选择                   |
| ------------------------------------------ | ---------------------------------------------------------------------------- | ---------------------- |
| 分解/PRD/交接文档 + Vue 2页面与独立 FastAPI mock | 页面、字段与接口合同可阅读、可运行、可联调；平台能力仍沿用现有服务             | 采用，符合用户后续授权 |
| 在现有 React 入院 Demo 中继续开发          | 可以立即复用 React hooks，但不满足指定组件栈，且混入大量已有未提交修改       | 不采用                 |
| 只输出静态图片/文字线框                    | 文件更少，但无法验证交互和前后端字段校验合同                               | 不采用                 |

必要工具：Vue 2.7负责页面状态，Element UI负责标准表单和弹层；Vite Vue2插件构建页面，独立 FastAPI 服务负责字段验证、mock 路由和固定目标的 AI 代理。无需路由库、全局 Store、新模型供应商或数据库。

## 5. 真实失败模式与防护

1. 认证失败仍保留前一个患者的数据：认证前清空身份与草稿，取消/超时/回首页清空会话；演示失败分支不得进入表单。
2. AI 乱填证件或覆盖人工输入：只允许 F03/F08/F13/F14 映射；只对空字段回填；候选校验失败不写入；身份类字段只来自认证快照。
3. 第二页确认提交时第一页手机号为空：从所有字段统一校验，跳回最早错误所在页，禁止提交。
4. 提交重复点击或结果不明：客户端需同步加锁；下一阶段采用服务端幂等键与结果查询，超时不能伪造成功。
5. 语音录制时取消患者会话，迟到结果污染新患者：校验会话代号与阶段，取消录制/请求并丢弃迟到结果；页面实现中以会话 generation 和 AbortController 防护。
