# 14 · 重新认证时清空旧办理会话

## 目标

每次成功重新认证后，之前保存的入院登记对话、事实字段和待确认修改不得在新办理中恢复或进入 AI 上下文。

## 设计

- 成功重新认证时仅撤销当前患者此前签发的演示身份令牌，并按当前登录用户和已认证患者删除其旧办理会话（包括该患者的各申请单会话）。会话删除依赖数据库级联同时删除对话 turn。
- 随后使用当前身份令牌绑定的新会话 ID 创建空白办理会话，只从当前认证档案初始化权威字段。
- 同一身份令牌重复选择申请单时复用现有会话，避免网络重试或重复点击清空本次正在办理的数据；首次并发选择通过原子创建/读取处理，不产生唯一键冲突。
- 删除范围不包括其他平台用户或其他患者；失败认证不删除任何会话。

## 验收

1. 完成一次模拟认证、选择申请单并保存对话和字段。
2. 同一患者重新认证并再次选择申请单，得到不同会话 ID；新会话不含旧 turns、facts、summary 或 pendingProposal；旧会话行（保存 facts/summary/pendingProposal）及其级联 turns 已删除，旧身份令牌不能再读写会话。
3. 同一新身份令牌重复或并发选择申请单，均返回同一会话并保留本次会话内容。
4. 其他患者或其他平台用户的会话及身份令牌不受影响；失败认证不撤销当前身份或清除会话。

## 测试与边界

- Repo 测试写入 turns 和 pendingProposal，再验证删除旧 session 行会清除其 facts、summary、pendingProposal 与级联 turns，并保留其他 owner/patient 的会话。
- API 集成测试覆盖重新认证新会话不恢复旧对话/字段，以及重复选择保持幂等。
- 验证 admission registration 的 repo/API 定向测试和 Demo 前端流程测试。
- 当前入院登记接口是模拟服务；验证不连接真实 HIS。
