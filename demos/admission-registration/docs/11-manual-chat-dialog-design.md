# 手动输入对话框设计

## 目标

将首页底部“手动输入”从单独的文本弹窗改为与图 2 对话功能一致的对话框，让用户在一个窗口内查看 AI 解读和回答，并选择手动或语音输入。

## 交互

**重点验收（P0）：关系或职业无法从自然语言可靠抽取/归一化时，不猜、不静默跳过；对话框必须给患者展示表单的标准选项并让患者点选。** 覆盖“她是我的女儿”未抽出关系，以及“职业改成护士”无法映射职业字典两类情况；选择值按手动修改保存。

- 左侧为 AI 对话区，显示用户输入、活动模型生成的简短回答、处理中状态和错误。主页接口返回固定白名单意图和不超过100字的回答；只有明确开始办理的意图能启动身份核验。流程问题由模型解释并留在首页；未实现的挂号、打印、报告解读和真实医院查询明确拒绝。
- 宽屏右侧为输入区，提供文本输入与发送、语音开始/结束入口。手机端改为消息气泡在上、紧凑输入栏在底部；通过切换按钮在文字和语音模式间切换。
- 首页语音栏的麦克风按钮直接打开此对话框并进入语音输入模式；对话框显示“开始录音”，用户再次点击后才启动录音。手动输入按钮仍以文字模式打开对话框。
- 录音状态、转写中状态和 STT 错误在对话框内可见；语音转写作为用户消息进入左侧记录。
- 首页和表单页的对话转写、AI 回复、处理中状态与语音错误只在对话弹窗内显示，不在底层语音区重复呈现；首页快捷按钮也把请求和固定提示写入弹窗消息记录。
- 表单对话询问固定选项字段时，在问题下显示表单已有的选项按钮；婚姻状况、职业、与患者关系统一点选，点击后直接填入并按手动修改记录。自由文本、电话和地区字段继续使用原输入方式。
- 当前表单页的必填字段全部完成后，对话框主动询问是否继续；确认后复用现有分页校验并自动进入下一页，选择暂不继续则留在本页。最后一页确认后进入最终核对页，不自动提交登记；对“继续”等明确的语音/文字答复执行相同行为。
- 首页底部固定语音栏缩小高度，避免与弹窗争空间。
- 首页的文本和语音输入调用当前活动模型，由模型按页面真实能力回答；页面流程答疑、开始办理、不支持功能和含糊需求分别返回答疑、进入身份核验、明确拒绝和追问。表单页继续调用现有字段补充对话逻辑。
- 首页消息只保存在当前页面内存中；关闭对话框仅收起并保留记录，识别到入院意图并切换至身份核验页时自动收起，重置办理流程时清除。表单页仍使用既有持久化对话记录。

## 实现边界

复用 `ConversationDialog.vue`，在 `App.vue` 中统一管理可见状态和消息展示；首页语音栏麦克风打开对话框并预选语音模式，对话框内按钮调用现有 `startRecording` / `stopRecording`。保留首页原有 `classifyHomeIntent` 流程及表单页 `applyAi` 流程。只改对话框入口模式、必要状态和测试，不触及登记后端、表单页持久化合同或其他页面。

## 验收与验证

- 首页点击“手动输入”后打开左右分区对话框，左侧显示输入和 AI 识别结果，右侧可进行文本和语音输入。
- 首页点击语音栏麦克风后直接打开同一对话框并选中语音模式；此时不自动录音，点击“开始录音”才开始；点击手动输入则打开文字模式。
- 手动文本与对话框内语音转写均触发首页意图识别；识别状态、失败提示和完成结果显示在左侧，进入入院办理时仍按现有流程切换到身份核验页。
- 首页快捷按钮触发后打开对话框，并在对话记录中显示用户请求和固定提示；表单页录音/文本的本轮内容在处理时和完成后均显示在对话框，不重复显示在语音区。
- 下一个缺失必填字段为婚姻状况、职业或与患者关系时，弹窗提供与表单相同的可选值；点击后精确写入对应字段，不调用 AI 再解析。其它字段不显示枚举选项。
- **P0：患者口述无法可靠映射关系/职业（包括修改已填写值时）时，保持原值并在对话框显示对应标准选项；点选后才写入并保存，不要求患者反复重说。**
- 当前页必填项完成后弹窗提供“继续下一页 / 暂不继续”；第二页提供“进入核对页 / 暂不继续”。确认通过既有分页校验，最后一步不触发登记提交；明确的语音/文字确认与按钮行为一致。
- 关闭后重新打开保留主页对话记录；识别到入院意图并跳转身份核验时对话框自动收起；重置流程后清空。表单页持久化对话行为不变。
- 表单页的现有对话补充及字段处理行为保持可用。
- 使用 Demo 前端现有 Vitest 测试与 typecheck/build 命令验证。
