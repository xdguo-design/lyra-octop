# 02 · 入院登记 PRD

版本 v1.2；日期 2026-10-21；状态：范围与字段基线已确认，原型和 mock API 已实现。技术栈依据用户最新指定：Vue 2 + Element UI；后端 Python 3.12 + FastAPI。

**单页核心规则：整个办理流程在一个长页面内向下追加。身份核验、申请单、两组登记信息、核对、结果是业务阶段；完成阶段以脱敏只读记录保留，当前操作追加在末尾。AI 问答按时间顺序保留。业务状态变化不得清除前序内容；完成/退出/超时/重新核验身份才开始清理或新流程。**

## 1. 问题与目标

患者在自助终端办理入院时，需要先确认本人身份，再补齐必要信息并核对；原图把对话、字段和交互散布在不同区域，易造成缺字段、过早提交和语音能力误解。目标用户为具备自助操作能力的患者及现场协助人员；遇认证失败或信息不一致时转人工。

交付成功标准：整个流程按业务阶段向同一页面追加，前序内容可回看；14个字段均有来源、约束和显示位置；前后端使用同一字段合同；所有R01–R10可追溯到界面、API与验收；主流程及认证失败/信息不全/提交失败/重复登记/超时分支有明确交互。不设虚构的临床效益或转化率指标。

## 2. 范围与权限

- 本次：文档线框原型、截图分解、PRD、Vue 2 可运行原型、Python API mock 服务、共享前后端字段合同、开发规范和自动化测试。
- 后续实施：读卡、HIS、EMPI、字典和登记结果一律 mock；平台维护 ASR/TTS；沿用当前入院 AI 提取接口；任何真正提交都需要患者最终确认。
- 不包含真实医院登记、支付、押金、床位安排、打印、短信、生产人脸比对、供应商语音配置或新建 AI 模型服务。
- 原型只使用虚构身份和当前进程内存中的模拟回执，不收集真实患者信息；生产同源集成须保留 Octop 登录态。患者核验与平台用户登录是两个独立信任边界，不能互相替代。

## 3. 业务阶段清单（同一页面）

| 页面 ID | 页面              | 入口/出口                               | 业务目的                     |
| ------- | ----------------- | --------------------------------------- | ---------------------------- |
| P01     | AI 首页             | 默认/清理后；点击入院入口进入 P02         | 对齐原型机器人、对话卡及入口 |
| P02     | 前置身份认证        | P01；成功 P03，失败留页重试/退出          | 仅当前认证身份可继续         |
| P03     | 入院登记信息（1/2） | P02/P04；下一页 P04                       | 姓名至详细地址               |
| P04     | 入院登记信息（2/2） | P03/P05；返回 P03、确认提交 P05           | 单位、婚姻/职业/紧急联系人   |
| P05     | 登记结果            | P04；完成回 P01，失败回 P04 重试          | 明示模拟成功/失败/已登记     |

“提交中”为不可编辑状态；认证中/失败/无档案为身份核验的子状态。身份后必须确认本人有效申请单；患者依次补齐两组登记信息，再在同页追加的核对区明确确认提交。取消和超时覆盖整个流程。表中的编号是业务定位编号，不是独立页面或路由。

## 6. 异常与隐私要求

- 认证失败/超时：明确反馈，返回首页或重试，清除已显示的患者身份。
- 身份成功但无档案：引导人工，不显示可填写患者表单。
- AI 空结果/超时：不得称“已填写”，保留转写、表单和编辑入口。
- 数据不全：定位到最早错误页；已填项保留；失焦不清空其他字段。
- 提交失败：P05显示未完成并允许回 P04 重试；网络未知时使用原幂等键查询。测试情景由 mock API 提供，不显示患者端情景选择器。
- 所有内容按文本渲染，禁止把患者转写或模型输出当 HTML。患者姓名/证件/电话/转写不进入普通日志、埋点或浏览器持久存储。
- TTS 使用脱敏文案，不逐位朗读完整证件与电话。状态提示保持中性，不因婚姻/职业/民族产生评价。

## 7. 非功能要求与依赖

目标Demo：患者端以原型竖屏画布为准，支持 Chrome/Edge 鼠标、键盘和触屏；依赖随构建产物分发，不依赖运行时 CDN。页面顶栏日期时间按本轮原型截图文案呈现，不作为业务数据。

平台认证、模型/语音需 Octop 登录态；请求有界超时；录音开始与结束均检查会话与阶段；取消会释放媒体资源。需接通平台后才可宣称语音和 AI 验收通过。

## 8. 交付判定

验收以 `05-acceptance.md` 为准。文档可评审不等于页面已开发或生产业务验收通过；全量医院字典、身份设备、真实云端语音、模型输出可靠性与真实 HIS 写入均没有在本轮验证。

## 9. 提交结果状态补充

P05包含模拟成功、明确失败、已登记、结果待确认四种子状态。提交超时/断线先进入结果待确认，使用原幂等键查询；未确定失败前禁用修改和重提。查询明确后转入对应结果。P05待确认时隐藏正常“完成”按钮，避免误导患者已办理成功。

P04提交中/P05待确认与普通未提交表单区分：患者端退出或空闲清理只清除屏幕上的个人信息，不把已发出的请求撤销或改为失败。mock提交适配器保留最小幂等记录，下一次同患者办理不能通过新会话/新幂等键绕过重复登记检查。跨刷新恢复与生产持久化属于后续实现需要明确并验证的边界，本轮不声称已经支持。
