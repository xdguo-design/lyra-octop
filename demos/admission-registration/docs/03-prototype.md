# 03 · 页面原型与交互规范

版本 v2.1；2026-10-21。视觉基准为用户提供的流程总图和身份认证对话图。本文为当前实现基线，覆盖旧版“独立步骤页替换内容”“身份后直接填表”“第二页直接提交”等规则。技术栈保持 Vue 2.7 + Element UI；医院身份、申请单、地区和提交仍是演示数据，不连接真实 HIS。

## 1. 全局布局与语音栏

- 整个入院登记只有一个长页面。身份核验、申请单、两组登记信息、核对和结果依次向下追加；已完成步骤以脱敏只读快照保留在上方，当前操作区在末尾。AI 提问、患者回答、识别和确认记录同样连续追加，不因阶段推进清空。完成/退出/超时/重新核验身份会清理当前记录。
- 浅蓝背景、Neusoft 顶栏、帮助入口。宽度适配视口并保持触控尺寸，高度由内容自然撑开；使用浏览器整页滚动，不限制一屏高度或给流程/消息区单独滚动。语音/输入栏滚动时贴底；新增回复滚动至最新内容，返回首页时重置整页滚动位置。
- 自动播报有独立喇叭开关，默认关闭；开启后每条新 AI 回复和追问依次播放。关闭时中止当前 TTS 并清空待播内容。每条消息旁的喇叭只播放该条，不改变开关；历史恢复和回看不自动重播。录音开始时停止播报。
- 底部语音栏按参考图2：圆形麦克风在左，波形与提示居中，手动输入在右；导航和设备序列号位于语音栏下方。录音开始后展示真实麦克风音量波形，静音时显示低幅静音状态，有声时波形按 RMS 音量变化。未录音时不显示录音波形。麦克风为“按住说话”手势：按下立即录音并显示全屏遮罩（居中“松开 发送 / 上滑取消”，底部波形胶囊），松手即发送；手指上滑超过约 80px 遮罩转红色“松开取消”，此时松手丢弃本次录音；按住不足约 0.6 秒提示“说话时间太短”。说完停顿约 3 秒仍会自动结束（等价松手）。弹窗内“按住说话”按钮同一手势；“语音输入 / 结束录音”按钮保留点击开始/结束，兼顾键盘与辅助操作。
- 录音最长60秒；空音频不上传。停止、取消、离页或异常时释放 track、AudioContext、动画帧和计时器。只存储转写/结构化字段，不持久化音频。
- 静音自动结束只在“确实说过话”之后生效：开麦后一直无声不会立刻中断，仍由手动结束或60秒上限收尾。
- 在表单阶段，语音或文字打开 AI 对话面板；AI提问、患者回答、识别结果和字段确认按对话顺序显示。底部语音栏仍可操作；面板关闭只隐藏面板，不清空表单或会话。
- 对话框底部录音时显示随麦克风音量变化的波形、正在录音/等待声音提示和“结束录音”按钮；打开麦克风及识别期间显示相应状态，说完停顿约 3 秒自动结束并进入识别，完成后恢复输入栏及草稿。

## 2. 同页追加的业务流程

`首页 → 身份核验 → 本人入院申请单 → 基本信息(1/2) → 补充信息(2/2) → 独立信息核对 → 登记结果`

业务状态与服务端会话控制当前区段的操作权限，阶段推进只向下追加。身份或申请单未通过时不能操作登记表单；申请单的科室、计划入院时间等为只读数据，不由 AI 补写。返回编辑也在末尾继续，保留此前记录；新会话清理本机患者状态。重新核验会清除旧身份的前端记录和此前办理会话。当前会话在有效核验期间最多保存24小时。

### P01 · AI 首页

- 展示机器人、问候语、四个参考图问题按钮、自助模式入口和底部语音栏；首页不显示患者姓名/电话。
- 四个快捷问题均可点击。入院快捷入口直接进入身份核验；手动/语音对话由当前活动模型按页面能力回答。明确要求开始入院登记才进入身份核验；询问页面功能或办理步骤时解释当前模拟流程并留在首页；挂号、打印、报告解读、真实医院查询等未实现功能明确说明不支持。不得提供诊断、治疗或用药建议，不得声称已核验、提交或办理成功；无法理解时追问。

### P02 · 前置身份认证

- 在首页流程记录下方追加身份核验区；完成后保留核验记录，下方继续追加申请单区。
- 零触登录卡按参考图比例展示读卡器、证件摆放提示、300秒倒计时及“模拟刷卡”操作。身份 mock 成功后查询本人有效入院申请单；失败时停留并允许重试。

### P03 · 本人入院申请单

- 身份核验后先列出本人有效申请单；申请单展示申请标识、脱敏患者、入院科室、计划入院时间、医生、开单时间、住院类型、诊断、病区和状态。
- 每人同一时间只有一份有效申请单，因此唯一有效单自动成为待确认项，不再显示单独的选择按钮；患者点击确认后才建立办理会话，服务端仍校验申请单归属和有效状态。同一核验令牌重复确认时复用当前会话。无有效单显示空态；检测到多份有效单时提示联系现场工作人员，不自动选择且不允许跳转表单。当前 mock 返回单科室和入院时间均有值，以 UI 文字标记所有模拟数据。

### P04 · 入院登记表单

- 基本信息页 F01–F08；补充信息页 F09–F14。字段、必填项、选项、脱敏和校验遵循共享字段合同。
- 对话首轮仍完整说明所需资料。患者回答不完整时，在消息末尾显示“补充必填信息”卡片，列出尚未填写的必填项、显示完成项数并询问当前字段；标准选项沿用表单字典，文字/语音可一次补多项。补充后刷新剩余清单，不重复追问已填项。必填完成后切为选填补充卡，明确跳过后收起；冲突确认中和最终核对页不显示补充卡。卡片使用原有选择/保存/校验流程，不新增提交权限或持久化字段。
- 身份核验字段及申请单信息只读。患者说出电话、籍贯/现住地址等多个字段时，服务端解析整句并回填全部符合字段合同的值；地区必须匹配地区树，不猜区县。已有确认值与候选冲突时生成待确认提案，在用户选择前保持旧值。
- AI上下文结构化存储：格式化 facts、申请单摘要、最近交互、重要字段和可链接 turn 历史；每轮上下文输入限制为6000 tokens。适配器提供 tokenizer 时使用精确计数；Qwen 等适配器未实现 tokenizer 时，按 UTF-8 字节数加消息开销做保守上限。仅发送当前 turn 加必要摘要/最近4轮。相同会话/轮次幂等；超过预算显示明确错误并保留转写。
- 录音和手工文字使用同一轮次接口。AI只建议字段和下一条追问，不改变用户/身份/申请单，也不代替患者确认。

### P05 · 同页信息核对

- 补充信息后在同页追加核对区，按申请单、基本信息、补充信息分组显示当前内容。修改时在流程末尾继续对应分组，前序快照保持只读。
- 每次编辑使旧核对版本失效。存在缺失必填项或待确认修改时不能确认。确认绑定 session revision；仅当前核对页上的明确按钮/受控语音提交意图可以提交。

### P06 · 登记结果

服务端返回模拟成功、明确失败、已登记或结果待确认时分别显示对应状态。重复提交使用同一幂等键；网络结果不明时查询原结果，不以模型文案伪装成功。成功后不显示真实医院已办理的误导文案。

## 3. 隐私、超时与失败提示

- 归档按Octop用户、演示患者和申请单隔离，保留24小时；录音不保存。重新核验后才可读取；退出清理前端状态。通用日志不得写入患者原话或音频。
- 300秒无操作提示继续办理，宽限超时后清理本地状态；网络中断后若需要重新核验，会清除旧会话并从新办理开始。旧请求、旧身份或旧 revision 的迟到响应不得覆盖当前状态。
- AI错误按429限流、上下文过长、超时/连接失败、语义无法理解区分提示；保留转写。未实现 tokenizer 不作为模型故障提示。不用“AI不可用”覆盖真实错误原因。
- 本 Demo 所有申请单/身份/登记结果都是模拟数据；AI模型运行需用户已登录 Octop，实际语音设备、真实 Qwen、PostgreSQL 和 HIS 不由本地 mock 测试代替。

## 4. 回归验收

自动测试：Vue全量 Vitest、typecheck、format check、production build；Octop领域/数据库/API集成测试；独立旧 Demo API 合同测试。浏览器两轮回归覆盖首页、申请单门槛、两页字段、语音/文本、修改接受/拒绝、独立核对、提交和恢复。真实麦克风/Qwen/HIS不可用时记录为未覆盖，不伪报通过。
