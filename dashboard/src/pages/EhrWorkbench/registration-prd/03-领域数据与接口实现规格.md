# 业务动作详细逻辑设计

## 1. 通用执行模型

- 分层：页面 → HTTP 适配 → 应用服务（挂号/患者/排班/预约/分诊）→ 领域对象（RegistRecord/VisitEncounter/ScheduleSlot/TriageSeat）→ 端口（ChargeLock/Insurance/Integration/Print）→ 外部系统。
- 幂等与并发：号源占用用服务端条件更新（行数 0 即失败，BR-01）；visitCode/挂号 ID 由数据库序列原子分配（BR-02）；同一患者同一时刻至多一笔在途窗口挂号事务；分诊坑位用条件更新防重复占用。
- 乐观锁：挂号记录携带 LAST_UPDATE_DATE/UPDATE_USER，改写校验版本。
- UNKNOWN 原则：跨系统结果未知（仅限已确认启用的 JH0105、医保、电子发票）落 UNKNOWN 状态只查询不重试，不当作 FAILED（BR-12）。
- 服务端校验：必填、临床限制、验重、发票余量、费别分流全部服务端执行；客户端提示仅为体验层。
- 旧实现差异不静默：003 客户端读改写号额、020 客户端 dispose 解锁 chargeLock 均为旧语义，V2 废弃并在差异表留痕。

## 3. 高风险动作详细逻辑

### 3.1 `WindowRegistService.submitRegist` 窗口挂号事务

以 020 PatadAmbEvnSyntheticServiceImpl.windowRegist（:288-1180，@Transactional）为事务范围基线；003 PatadAmbEvnImpl.windowRegist（:301-564，未见事务注解）的行为差异在步骤内标注。

1. 读取配置快照：Econ_Use_Amb_Invoice、Reg_TriageCOntrol（Legacy 原拼写 COntrol）、ECON_CHARGECHANGEACOUNT、ECON_CHANGEACOUNTTYPE、ECON_IS_ACC_CHARGE；任一缺失按 BR-15 提示原文。
2. 患者主索引匹配：patMiCode 为空且 cardCode 非空且 cardType="1" 时按姓名+证件号查 REG_PAT_MI，命中首条回填（020 :288-310）；新建患者取序列置 ACTIVE（:469-575 段）。
3. 发票预检查：按 createUser+noType 查当前收据号；无票且 Econ_Use_Amb_Invoice=1 → 提示返回（BR-08）。失败分支：不抛异常，返回 message（Q-09 现行性）。
4. 支付与账户校验：扫描 EconRcptPayList 取首个 payAmount>0 条目为 payWay/selfAmount；普通账户余额不足调 getCanChargeAccount，空则拒绝（020 :329-468）。失败分支：余额不足显示充值补差（F-047）。
5. 排班解析：按科室/医生/号类/排班 ID + DB 当天日期重查排班，重写 schedulingRegId；停诊/过时在此步拒绝（BR-01 补强）。
6. 号额原子扣减：`UPDATE AMB_SCHEDULING_REG SET REG_REMAINING_NUM=REG_REMAINING_NUM-1 WHERE ID=? AND REG_REMAINING_NUM>0`；行数 0 抛错回滚整事务。003 对照：此步无原子扣减（旧缺陷，不继承）。
7. 挂号写入：insertPatadAmbRegist → AMB_REGIST（主键 AMB_REGIS_ID.nextval；visitCode 取 AMB_VISIT_CODE_ID.nextval）；statusCode=NO_CLINIC、source、isCharge、regClass、erFlag、poorType 等按 VO 落库；黑名单查询在此段（020 :3385-3505，用途 Q-12）。
8. 序号与分诊：allocate() 计算registNo/seeDate（唯一约束为 V2 补强）；按 Reg_TriageCOntrol 分 NoTriage/Triage/TriageReg/TriageAndReg/AutomaticTriage 写 AMB_TRIAGE；Triage 分支查最小可用坑位 useRegsitNo（Legacy 原拼写）置 REG_TAKE_FLAG=1，找不到坑位不阻止挂号（020 旧行为，V2 改为显式降级策略，Q-16）。
9. 计价与收费明细：排班 price>0 才建检查医嘱/价目映射/EconAmbPatientCharge（020 :678-795）；失败分支：价目缺失阻断（链路 Q-17）。
10. 结算与票据：ambRegistSetting 成功才回写收据号；invoiceType 分普通/电子票，电子票中间表非 1 条抛错；电子发票 API 失败记附加错误不回滚资金（020 :796-860）。
11. 账户变更：更新 ECON_AMB_ACCOUNT(\_RECORD)；新账户要求 ACTIVE MED_CARD 否则抛错（020 :865-1158）。
12. 提交后：打印指引单（F-012）；chargeLock=1 由收费事务加锁（BR-03）；020 客户端失败补偿（释放首排班 UpdateScheduleCommand）保留为降级路径，不得替代服务端事务。

### 3.2 `RegistCancelService.cancel` 退号编排

1. 前置断言：挂号记录存在且状态可退；statusCode=CLINIC 时要求确认（「已经接诊，是否要继续退号？」）。
2. 口令确认：Patad_CancelRegist=1 时校验操作员口令（020 PatadCancelRegistLoginUserModel）。
3. 退号校验以 020 潼南已验证行为和院区参数为准：已缴费单据/医嘱、Patad_CancelRegistDiag 控制的在诊诊断及电子票据入账按 020 规则/现场开关校验。CLINIC 接诊确认如仅能在 003 找到证据，标 SUPPLEMENT-PENDING，未确认前不得作为目标强制拦截。具体 API 路径须以 020 调用证据及新系统契约复核。
4. 已收费：跨包调 judgeCancelRegist（退费+医保反结算；工伤 09 走 cancelRegisterSettlement 三段，003）；资金结果归《门诊退费》/《门诊医保》包。
5. 未收费：020 PUT patad/evn/amb/cancel/regist → 置 statusCode=BACK_REGIST、消息「退号成功！」。003 的 patad/evn/amb/cancelRegist 与 cancelDoctorRegist 路径仅作兼容调查项，不是默认契约。
6. 释放：号额回补、坑位 REG_TAKE_FLAG=0（取消分诊/退号）；预约记录联动失效。
7. 事后：默认不推送 JH0105。只有业务确认启用 F-051 后，才异步推送并记录状态、失败留痕和补偿（BR-12）。

### 3.3 `examineForRegist` 验重两版对照（已回源）

- 003：patMiCode+permCode+trunc(REGIST_DATE) 动态查询（AmbRegistMapper.xml:852-912），数 BACK_REGIST 达 3 阻止（PatadAmbEvnImpl.java:1973-2025）；72 小时提示确认分支在服务端被注释，页面保留 YES/NO 处理。
- 020：要求排班 ID 或（科室+号类）；查当日排班回填；当日同排班挂号查询（AmbRegistMapper.xml:2671-2728），patad_CancelRegistNum 默认 3；JVM Calendar 日界与 DB 时钟差异必须收敛（V2 统一 DB 时钟）；catch(Exception) 放行属旧缺陷不继承。
- 剩余未闭环：跨院区/费别分支（Q-14）。

## 4. 方法实现要求

- 所有状态校验、数量校验、资格校验、权限校验在**服务端**执行；前端只做预检与提示。
- 金额统一两位小数、按 Econ_Rounded 舍入；禁止浮点直接求和；减免金额服务端计算。
- 禁止在 Command/Service 中散落读取配置键；统一经参数服务初始化（04 章 15 节）；同名键跨现场语义不等价，禁止按名字假设。
- 跨系统写操作（JH0105/医保/电子发票）必须有幂等键 + UNKNOWN 落库 + 查询恢复路径；不允许"失败即重试"。
- 序号分配必须有（排班ID+序号）唯一约束兜底；003 无 order by 的 listByScheduleId 查询模式禁止照搬。
- 技术可靠性机制（Outbox、重试表、消费去重）属于基础设施，不作为挂号领域业务方法建模。

挂号登记域自有实体：RegistRecord（AMB_REGIST）、ScheduleSlot（003 AMB_SCHEDULE / 020 AMB_SCHEDULING_REG）、VisitCode（序列发源）、TriageSeat（AMB_REGIST_NO）、TriageRecord（AMB_TRIAGE）、AppointmentRecord（003 AMB_SCHEDULE_APPOINTS/AMB_PERM_APPOINTS / 020 AMB_APP_REG）、PatientMainIndex（REG_PAT_MI）、PatientCard（REG_PAT_CARD/PAT_RCMC）。只读引用（不拥有）：ECON_AMB_ACCOUNT(\_RECORD)、ECON_RCPT(\_PAY)、收费明细、票据管理（归门诊收费包）；医保登记（归门诊医保包）；队列调度（归门诊分诊叫号包）。

### 3.3 数据保存规则

- 状态落库：NO_CLINIC/CLINIC/BACK_REGIST、REG_TAKE_FLAG、CHARGE_LOCK 每次迁移写审计（操作人+时间+原因）。
- 快照不可变：患者姓名/性别/出生日期/费别在挂号时快照落 AMB_REGIST，后续档案变更不回写历史挂号（020 已有"更新 REG_PAT_MI"支路，挂号侧以快照为准）。
- 金额：两位小数；减免明细与合计分列（TOT_COST、减免列）；舍入口径 Econ_Rounded 按现场核验。
- 序列：AMB_REGIS_ID/AMB_VISIT_CODE_ID 由数据库序列分配，禁止应用侧自增。
- 退号不物理删除：BACK_REGIST 终态保留原记录，重新挂号产生新记录（BR-14）。
- 未闭环链路（Q-13/Q-15/Q-16/Q-17）在 Mapper 全链路核验前，不得把"看到了 INSERT"当作流程复现。

## 合并模块：19-后端服务详细设计说明

# 后端服务详细设计说明

## 1. 服务设计统一约定

### 1.1 服务方法必须包含

权限校验、状态前置断言、幂等/条件更新判定、业务校验（号源/临床/验重/发票/资格/配置）、状态迁移与审计、统一结果封装、异常到错误码映射。

### 1.2 统一请求上下文

操作人（operatorId、岗位、权限集）、院区 hospitalCode（服务端登录上下文覆盖，不信任客户端）、会话配置快照（进入页面时读取的开关/参数集）、traceId、lockUser（visitCode 锁定人）。

### 1.3 统一结果结构

`{ code, message, data }`：业务失败返回业务错误码与可读 message（Legacy 原文口径）；号源/坑位条件更新失败返回行数 0 对应错误码。

## 2. `submitRegist` 窗口挂号服务详规（PROPOSED）

### 2.1 服务职责

接收患者+排班+支付+发票的完整提交，完成校验-占号-事务落库-结果返回；对齐 020 @Transactional 范围（14 章 3.1 十二步）。

### 2.2 逻辑方法签名

`RegistResult submitRegist(RegistCommand cmd, OperatorContext operator)`

### 2.3 请求字段

| 字段                         | 类型      | 必填 | 说明                                                           |
| ---------------------------- | --------- | ---- | -------------------------------------------------------------- |
| patMiCode                    | ID        | 条件 | 主索引；空时按 cardCode+cardType 匹配/新建                     |
| cardType/cardCode            | 文本      | 条件 | 卡标识；cardType="1" 支持匹配回填                              |
| scheduleId                   | ID        | ✓    | 排班（020 schedulingRegId / 003 scheduleId）                   |
| feeType/patIdentity/poorType | 字典      | ✓    | 费别/身份/贫困（BR-07 必填集）                                 |
| payList                      | PayItem[] | ✓    | 支付条目（首个 payAmount>0 为 payWay/selfAmount，Legacy 语义） |
| invoiceNo / eInvoice         | 文本      | 条件 | 发票（BR-08 校验余量）                                         |
| requestId                    | 文本      | ✓    | 幂等键                                                         |

请求示例：`{ "patMiCode":"P10001", "scheduleId":9001, "feeType":"08", "payList":[{"payCode":"XJ","payAmount":10.00}], "requestId":"R202610140001" }`

### 2.4 请求前置校验

患者已定位且 ACTIVE；排班 ACTIVE/未停诊/未过时（BR-01）；必填集 Patad_PatRequired（BR-07）；儿科/妇科（BR-05）；便民资格（BR-06）；examine 验重（BR-04）；发票/支付方式（BR-08）；权限（BR-13）；chargeLock=0（BR-03）。

### 2.5 执行流程

见 14 章 3.1 步骤 1—12；号额扣减与 AMB_REGIST 写入同事务；跨系统副作用事务外处理；JH0105 仅在业务确认启用后接入补偿。

### 2.6 返回字段

挂号 ID、visitCode、registNo、seeDate、statusCode=NO_CLINIC、费用明细（含减免）、发票号、打印回执。

成功返回示例：`{ "code":"OK", "data": { "registId":100234, "visitCode":"V202610140001", "registNo":5, "statusCode":"NO_CLINIC", "totCost":10.00 } }`

失败返回示例：`{ "code":"SOURCE_SOLD_OUT", "message":"已无号源！" }`；`{ "code":"DUP_REGIST_CONFIRM", "message":"该患者满足一次挂号管三天…是否继续挂号？", "data": { "needConfirm":true } }`

### 2.7 数据读取与保存

写：AMB_REGIST、AMB_SCHEDULING_REG（条件扣减）、AMB_REGIST_NO（坑位）、AMB_TRIAGE（按 Reg_TriageCOntrol）、收费明细/收据/结算（收费包同事务范围）、审计表；读：REG_PAT_MI/REG_PAT_CARD、排班、价目、字典快照。

### 2.8 错误码与处理

SOURCE_SOLD_OUT（号源不足）/ DUPLICATE_REGIST（验重阻断）/ CONFIRM_CONTINUE（确认继续，留痕）/ ELIGIBILITY_BLOCKED（资格/临床）/ INVOICE_INSUFFICIENT（发票不足）/ PAYWAY_MISSING（无支付方式）/ CONFIG_MISSING（开关/参数缺失，含 Legacy 原文）/ VERSION_CONFLICT（乐观锁）/ CHARGE_LOCKED（锁定中）。

### 2.9 并发、幂等与安全

requestId 幂等防重复提交；号额条件更新防超号；序号唯一约束防重号（补强）；visitCode 序列原子；金额服务端计算；操作留痕含原因。

## 3. `cancelRegist` 退号服务详规（PROPOSED）

### 3.1 职责与签名

`CancelResult cancelRegist(CancelCommand cmd, OperatorContext operator)`；cmd 含挂号引用、口令、确认标记、原因。

### 3.2 前置与流程

见 14 章 3.2 步骤 1—7；已收费分支跨包调用（退费+医保反结算）以幂等键（挂号引用）防重复发起，UNKNOWN 只查询。

### 3.3 错误码与恢复

ALREADY_CLINIC_CONFIRM（已接诊确认，按 020 核验/补充项待确认）/ PASSWORD_REQUIRED（口令）/ CHARGED_ORDER_EXISTS（已缴费医嘱）/ DIAGNOSIS_EXISTS（在诊诊断）/ INVOICE_ACCOUNTED（票据已入账）/ REVERSAL_UNKNOWN（反结算未知→人工）/ PUSH_PENDING（JH0105 待补偿）。恢复：处理后按挂号引用重查状态重试。

## 4. `holdSchedule` 号源占用服务详规（PROPOSED）

### 4.1 职责与签名

`HoldResult hold(Long scheduleId, String requestId)`：条件扣减 REG_REMAINING_NUM；`release(Long scheduleId, String requestId)` 对冲回补；003 侧 AMB_SCHEDULE.REGIST_USE_NUM 兼容视图只读。

### 4.2 约束

行数 0 返回 SOURCE_SOLD_OUT；请求号幂等（同请求重复占用返回原结果）；过期未提交由事务边界保证不悬挂（同一事务，无独立过期释放需求，Q-16 结论前不引入两阶段）。
