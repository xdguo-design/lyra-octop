# 门诊挂号登记产品开发文档导航

版本：v0.2（评审稿）

**基线决议（2026-11-02）：020 潼南为默认业务事实基线；003 东港只作补充证据。003 独有行为只有在 020 未覆盖且业务负责人逐项确认后才进入目标需求。**

**完整性决议：** F-001～F-056 全部保留并逐项标记目标处置；“待确认 / 延期 / 跨域引用”不等于删除，也不允许把 003 行为自动补成 020 规则。

**动态交付：** PRD HTML 内含 P01～P05 的表单、列表和状态交互页面，不以静态截图作为交互底图。操作会驱动本地演示数据和页面状态变化；动作目录从 02 章 E 动作表读取，并联动 F/E/BR、参数开关、业务方法说明及源码证据。原型不调用真实挂号、收费、医保或分诊写接口；原型通过不等于业务验收通过。

适用范围：门诊挂号窗口/工作台、预约与取号、挂号分诊台（挂号侧）、建卡与特殊人群建档

## 四、文档边界

- `01` 定义业务范围和功能基线（F-001～F-056 功能清单与继承矩阵），不描述具体代码实现。
- `02` 定义页面、元素、动作（E-xx）和页面时序，不定义数据库表结构。
- `03` 定义领域数据（AMB_REGIST 字段表等）和服务接口，是开发实现的核心依据。
- `04` 定义跨接口共用的状态（NO_CLINIC/CLINIC/BACK_REGIST、CHARGE_LOCK）、规则（BR-01～BR-16）、开关和异常处理。
- `05` 定义系统边界、外部依赖、联调和验收测试（A-01～A-14，对应本包测试页 V-01～V-14）。

## 六、与相邻包的关系

- **编号共用**：F-001～F-036 沿用 `prd/traceability-registry.json` 中 `outpatient-registration` 包登记编号（F-008=建卡），F-037～F-056 为本包扩展，不自造第二套编号；BR/A/Q/E 为本包自有编号，包内全局唯一。
- **门诊收费包**：挂号收费动作与收费事务、日结、挂号日报归收费包；本包负责锁号联动（CHARGE_LOCK，规则本体 04 章 BR-03）、算费校验与窗口挂号事务内嵌收费写入；收费侧只读投影挂号结果。
- **门诊医保包**：医保登记细节（busiType=01 弹窗内容、待遇识别、反结算）归医保包；本包保留费别分流触发点与慢特病资格校验调用（BR-06/BR-09）。
- **门诊医生站包**：生成就诊后的接诊流转（NO_CLINIC→CLINIC）归医生站包；本包提供状态与 visitCode。
- **门诊分诊叫号包**：排队叫号调度、过号、优先级规则归分诊叫号包；本包保留挂号分诊台动作（F-029～F-036）与坑位占用（F-050），Q-11 交接。
- **门诊退费包**：退号触发的退费与医保反结算归退费包；本包 BR-11 定义触发条件与状态结果（BACK_REGIST）。
- **跨包调用语义**：跨包结果 UNKNOWN 一律转查询/人工复核，不当作失败重试（BR-12/BR-14）；020 RegistCommand.java:127-145 证实窗口与第三方渠道共用便民门诊资格校验，线上渠道边界见 01 章"一期不包含"（Q-10）。

## 七、背景归档

本套文档由本包 `prd-doc.html`（页面级 PRD，003 东港/020 潼南源码逐行阅读）、`spec.html`（业务流程 8 环节）、`analyzer/`（调用链分析快照、数据与接口目录）、`call-analysis*.html`、`reg-canvas.html`/`prototype.html`（交互事实）与 `test.html`（V-01～V-14 验收矩阵）合并重构而成。业务口径以页面级 PRD 为追溯源；源码证据以调用链分析页与 `analyzer/data/legacy-source-snapshots.js` 的证据编号为准。

新版前后端可以完全重写，不依赖旧代码路径；但旧产品功能必须通过继承矩阵和验收矩阵完整继承或升级。编写顺序 01 → 04 → 02 → 03 → 05 → 00（本索引最后汇总）；证据纪律与编号规则见 prd-doc-suite。
