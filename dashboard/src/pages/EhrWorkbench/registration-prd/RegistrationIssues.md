## Issue 列表

### ISS-REG-01 冻结 020 潼南目标基线及 003 补充决策

- **类型 / 优先级**：业务决策 / P0
- **范围**：逐项审阅差异台账，确认 003 独有能力是否纳入；默认不启用、不验收。
- **追溯**：F-001～F-056；Q-01～Q-21；PRD 01、04、05。
- **验收标准**：每条差异有业务结论、确认人/日期、目标开关和验收用例；所有未结项仍可见且不会被实现默认行为覆盖。
- **依赖**：无。

### ISS-REG-02 导出并核验院区参数、字典及开关

- **类型 / 优先级**：配置与数据 / P0
- **范围**：核验 04 章参数表中的院区/医院/用户级参数、默认值、缺失行为和缓存刷新来源。
- **追溯**：BR-04～BR-09、BR-13、BR-15；Q-08、Q-18～Q-20；A-03、A-05～A-09。
- **验收标准**：提供参数键、现场值、数据类型、适用范围、修改权限、刷新方式、缺失提示和回滚值的签字清单；未知值仍标 `UNKNOWN`。
- **依赖**：ISS-REG-01。

### ISS-REG-03 实现患者检索、识别与唯一患者确认

- **类型 / 优先级**：功能 / P0
- **范围**：窗口患者查询、多通道读卡、候选去重、患者信息回填；多条命中时强制人工确认。
- **追溯**：F-004、F-005、F-006、F-007、F-053；P01；BR-07。
- **验收标准**：卡号/证件号/姓名检索均按权限执行；多命中不会自动选择；读卡失败可回到手工查询且不会丢失录入；必填和证件校验由服务端复核。
- **依赖**：ISS-REG-02。

### ISS-REG-04 实现建卡、查重、健康卡与特殊人群档案

- **类型 / 优先级**：功能 / P1
- **范围**：建卡/补卡/退卡留痕、身份证读取、健康卡绑定、三无及新生儿档案处理。
- **追溯**：F-008、F-009、F-021、F-022、F-052；P05；A-09。
- **验收标准**：重复患者创建前提示已有档案；无授权不能绕过查重；特殊人群按现场已确认开关走差异流程；卡费项与展示开关按参数生效。
- **依赖**：ISS-REG-02、03。

### ISS-REG-05 实现排班、号源查询与服务端原子占号

- **类型 / 优先级**：功能 / P0
- **范围**：按日期、科室、医生、时段查询；处理放号、停诊、剩余号额、限诊及选中态。
- **追溯**：F-001、F-002、F-015、F-016、F-043、F-054；BR-01；A-01、A-02。
- **验收标准**：提交时服务端以条件更新扣减号额；并发争抢余 1 号仅一笔成功；停诊/过期/余号 0 一律拒绝；页面缓存不能作为号额事实。
- **依赖**：ISS-REG-01、02。

### ISS-REG-06 实现窗口挂号命令、就诊流水与事务回滚

- **类型 / 优先级**：功能 / P0
- **范围**：校验患者、号别、费别、重复挂号、临床限制、权限、分诊/收费关联并提交挂号记录。
- **追溯**：F-010、F-014、F-018、F-041、F-044、F-049、F-055；BR-02、04、05、09、10、14；A-04、05、10。
- **验收标准**：visitCode 全局原子唯一且不复用；重复请求幂等；本地事务任一步失败整体回滚；重复挂号确认继续需留痕；服务端复核患者和号源条件。
- **依赖**：ISS-REG-03、05、08、09。

### ISS-REG-07 对接收费域并完成挂号收费上下文交接

- **类型 / 优先级**：集成 / P0
- **范围**：定义挂号向收费域传递的患者、visitCode、费别、号别与费用预览；消费收费成功、失败和 UNKNOWN 结果。
- **追溯**：F-003、F-017、F-040、F-046、F-047、F-056；BR-03、08、10；A-06～A-11。
- **验收标准**：chargeLock 服务端互斥且异常路径也解锁；发票和支付方式缺失按规则阻断；费别减免/账户补差交由收费域 PRD；UNKNOWN 进入查询/人工复核，不重复扣款。
- **依赖**：收费域契约、ISS-REG-06、08；关联已有 [门诊收费真实交易 Issue #34](https://github.com/xdguo-design/product_design/issues/34)。

### ISS-REG-08 冻结医保、退费、电子票据的跨域契约

- **类型 / 优先级**：集成与业务决策 / P0
- **范围**：确认门诊医保登记、慢特病资格、退费和电子票据的触发条件、输入输出、超时、UNKNOWN 与责任边界。
- **追溯**：F-045、F-048；BR-06、09、11；Q-10；PRD 00 §六。
- **验收标准**：接口契约与所属 PRD 一致；挂号侧只消费明确结果；跨域未知状态先查询/人工复核；挂号包不复制医保/收费内部规则。
- **依赖**：医保、收费、退费 PRD 负责人确认；关联 [门诊收费真实交易 Issue #34](https://github.com/xdguo-design/product_design/issues/34)、[退费真实交易 Issue #35](https://github.com/xdguo-design/product_design/issues/35) 与[医生站事件契约 Issue #36](https://github.com/xdguo-design/product_design/issues/36)。

### ISS-REG-09 实现退号校验和退号事实状态迁移

- **类型 / 优先级**：功能 / P0
- **范围**：按 020 潼南规则核验口令、已缴费单据/医嘱和诊断开关；按已确认跨域契约处理已收费退号；成功置 BACK_REGIST。
- **追溯**：F-011、F-013、F-025、F-055；BR-11、12、14；A-12。
- **验收标准**：未确认的 003 接诊确认和医生站专用撤销不进入默认逻辑；020 电子票据入账校验按已确认参数执行；失败不产生 BACK_REGIST；重复退号返回可解释结果；操作人和原因可追溯。
- **依赖**：ISS-REG-01、02、08；资金逆向细则衔接[退费真实交易 Issue #35](https://github.com/xdguo-design/product_design/issues/35)。

### ISS-REG-11 实现挂号分诊和坑位占用生命周期

- **类型 / 优先级**：功能 / P1
- **范围**：分诊、改诊、取消分诊、开停诊联动、候诊坑位占用释放。

### ISS-REG-12 实现退号集成推送（仅业务确认后启用）

- **类型 / 优先级**：补充能力 / P2 / `SUPPLEMENT-PENDING`
- **范围**：仅在业务确认采用 003 JH0105 行为后实施；配置默认关闭。
- **追溯**：F-051；BR-12；A-14。
- **验收标准**：未确认前退号不调用 JH0105；确认启用后才验证异步幂等、失败留痕及补偿；推送失败不回滚已成功退号。
- **依赖**：ISS-REG-01、集成平台契约。

### ISS-REG-13 实现打印、指引单与原号重打

- **类型 / 优先级**：功能 / P2
- **范围**：挂号成功后的指引单打印、历史挂号原号重打、打印失败恢复。
- **追溯**：F-012、F-026、F-027；P01/P02；BR-16。
- **验收标准**：打印动作不重复创建挂号/收费事实；重打权限留痕；打印失败可重试且票据号不变；代煎信息以所属业务域为准。
- **依赖**：ISS-REG-06、07。

### ISS-REG-14 实现权限、审计和操作确认

- **类型 / 优先级**：安全与审计 / P0
- **范围**：挂号、退号、建卡、排班、分诊等动作的授权、口令确认与审计事件。
- **追溯**：F-010、F-013、F-025、F-031；BR-13；Q-04。
- **验收标准**：所有写动作服务端鉴权；权限不足不能通过改请求绕过；审计记录操作人、时间、对象、结果和原因；实际权限项在院区确认后落表。
- **依赖**：ISS-REG-01、02。

### ISS-REG-15 建立 56 项功能到页面、方法、证据及验收的追溯检查

- **类型 / 优先级**：质量门禁 / P1
- **范围**：确保每个 F-ID 至少关联一个页面动作、目标方法、BR/参数、源码证据状态及验收项。
- **追溯**：F-001～F-056；E-01～E-A07；BR-01～BR-16；A-01～A-14。
- **验收标准**：自动或人工报告中不得有未归属 F-ID；待确认、延期和跨域引用有明确处置；动态 Demo 的每个动作项均能打开对应方法说明与来源证据。
- **依赖**：ISS-REG-01～14；字段证据跟踪参考[医生站事件契约 Issue #36](https://github.com/xdguo-design/product_design/issues/36)。
