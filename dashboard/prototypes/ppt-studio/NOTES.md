# PPT 工作室 · 一次性页面原型

## 问题与假设

用户已选择以 hugohe3/ppt-master 为核心，提供专用制作页，包括大纲、逐页修改、预览与 PPTX 下载。本轮只回答“页面看起来和操作起来是否合适”，不安装技能，不连接模型，不修改正式路由、认证、数据库或生产资源。示例演示稿为界面设计用途的原创文案，不代表真实客户案例、实测数据或平台已完成的功能。原型以桌面 1440×900 为主要尺寸，兼容较窄窗口。

## 三个方向的共同设计输入

直接用户是需要完成产品介绍、工作汇报和方案提案的普通平台用户。他们首先要理解作品当前处于大纲、生成还是修改阶段，其次要能看见当前页和其他页之间的关系，最后要明确每次修改的影响范围。不能把技能命令、运行目录、模型工具日志等内部细节放在主操作流里。页面使用项目已有的 Octop 品牌资产，沿用浅色底、清晰文本、细分隔线和紧凑的工具栏；演示稿本身使用纸白、森林绿和衬线标题，区分产品界面与作品内容。没有业务必需的摄影图片，因此不添加装饰性图片或外部网络资源。

共同内容是七页“团队 AI 工作方式提案”示例，覆盖封面、现状、协作流程、工作台、应用场景、推进步骤和结束页。页面必须显示作品名、页数、当前页、内容编辑入口、AI 单页修改入口、预览和导出入口。原型所有交互仅操作内存；刷新恢复初始示例，不能显示“已保存到云端”。内容输入必须作为纯文本处理，避免用户输入变成 HTML。模拟 AI 修改须明确标示，只能演示确定性的文案或布局变化，不能声称真正调用模型。导出入口解释正式版合同，不提供伪造的 PPTX。

A 为三栏制作工作台：左缩略图、中画布、右修改面板，便于连续精修；B 为大纲与页面总览：弱化逐页导航，把页面结构集中展示，便于整理叙事顺序；C 为沉浸画布：深色舞台、底部胶片导航、右侧编辑，便于聚焦单页。三个方向通过底部切换栏及 URL 的 variant 参数切换，共享当前编辑内容，避免比较布局时丢失输入。选定方向前不实现正式功能，也不创建 direction-approved.md 冒充用户批准。

## 运行

在仓库根目录执行：

```powershell
python -m http.server 8767 --bind 127.0.0.1 --directory dashboard/prototypes/ppt-studio
```

访问 http://127.0.0.1:8767/ 。也可以直接打开 index.html；品牌图已内嵌，不需要联网。

## 验证与限制

检查三方向切换、页面切换、大纲编辑、标题与正文同步、新增页、模拟单页布局修改、预览和导出说明。主要失败场景为输入注入、切换方向丢失编辑、窄屏操作溢出；分别以文本转义、共享内存状态和响应式布局处理。不为一次性视觉原型新增生产配置、依赖、Docker 或 CI。

2026-10-24 验证：通过一次性 Node/JSDOM 断言检查三方向、页面切换、HTML 输入转义、切换保留编辑、单页修改、新增页、放映弹窗、导出提示、大纲与新建示例。HTTP 返回 200。内置浏览器实际检查三方向，并保存 `preview-A.png`、`preview-B.png`、`preview-C.png`；修正总览卡片高度和画布自适应后复看通过。未运行全仓 `make all`，未实测移动设备或真实模型/导出服务。
